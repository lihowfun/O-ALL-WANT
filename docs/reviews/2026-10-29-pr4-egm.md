## Findings

### [P1, fixed] OAW rejects unrelated, host-specific skills

`doctor` enumerated every local skill and wiki lint reused the portable OAW
validator for every package. A valid Claude-specific field such as
`disable-model-invocation: true` caused both commands to exit 1. This prevents
coexistence with host-native packages. EGM's seven skills contain that field;
installing a plugin through a host's separate plugin store is not itself proof
that this local-directory path was exercised.

Reproduction on the reviewed head: install the knowledge profile with
`--host claude`, create `.claude/skills/third-party-review/SKILL.md` with name,
description, that boolean field and a nonempty body; run doctor and installed
`wiki_sync.py lint`. Both report `unsupported portable frontmatter field`.

Fix: installed OAW lint uses the declared managed/custom skill inventory;
doctor additionally checks required OAW packages. Third-party validation is
reported as host-owned/unknown. OAW's own broken, missing and customized packages
remain checked. Explicit `validate_skills.py --all-packages` retains the strict
portable-subset audit, without claiming to certify a host's schema.

Regression: actual both-host knowledge installation, external Claude field,
doctor + wiki + standalone lint, explicit strict audit, then a deliberately
broken OAW package. External file bytes must remain unchanged throughout.

### [P2, corrected in this review] Scope and source claims need versions

PR text and review handoff still described the older 82-test revision. README
listed conceptual influences as “Used” with mutable links, but the historical
records did not pin upstream versions. That is insufficient for a reproducible
dependency claim. The new [source ledger](../releases/2.0.0-sources.md) separates
actual workflow dependencies, evaluated-only EGM and unversioned historical
influences. An upstream SHA fetched today cannot retroactively prove which
version inspired v1.

### [P2, future plan] Manual-only behavior is not verified across hosts

EGM's Claude frontmatter disables model invocation, but its Codex
`agents/openai.yaml` files contain interface metadata without an explicit
`policy.allow_implicit_invocation: false` policy. This does **not** establish
Codex trigger behavior. Record each host/version as untested until its native
invocation/negative-trigger tests run. Do not silently edit upstream packages
to manufacture parity. [Pinned source](https://github.com/google/elephant-goldfish-model/blob/f0ba151b252c9abf1318d9fe857a43265d06de89/skills/egm-review/agents/openai.yaml).

### [P2, future plan] A marketplace install is not a SHA lock

The official install commands identify a marketplace/repository. They do not
by themselves prove that the installed bundle equals the evaluated commit.
Capture the installed manifest version and content/tree hashes; mark the run
unverified if the host cannot establish identity. Do not invent a pinning flag.
Manifest `0.1.0` is package metadata, not proof of a published release artifact
or of host support. [Upstream release policy](https://github.com/google/elephant-goldfish-model/blob/f0ba151b252c9abf1318d9fe857a43265d06de89/docs/releases.md).

### [P2, future plan] Host-specific limits and protocol tests need narrower claims

The 24,000-byte skill-body test is explicitly an **Antigravity** constraint.
OAW currently targets Codex and Claude; do not impose that number as their
universal schema limit. [Pinned test](https://github.com/google/elephant-goldfish-model/blob/f0ba151b252c9abf1318d9fe857a43265d06de89/tests/unit/test_skill_load_limits.py).

There are 30 declared scenario IDs across seven YAML files (4/4/8/1/2/3/8).
These required/forbidden-pattern assertions measure protocol compliance.
They do not establish better designs or greater defect detection. The plan's
separate seeded-defect outcome suite is the right direction; include false
positives, unsupported fixes and cost, rather than rewarding EGM wording alone.

## Keep, replace, retire, defer

| Area | Decision | Reason / next evidence |
|---|---|---|
| Host reasoning, permissions, sessions, personal memory | Leave to native hosts | No OAW lifecycle, mandatory report or memory nudge |
| Generic reasoning advice in `oaw-evidence` | Replace with actual OAW CLI contract | Bounded literal recall, cursor invalidation and explicit record writes are the distinct capability |
| Safe init/migrate/doctor | Keep | Package ownership and preservation remain useful independently of EGM |
| Portable evidence helper | Keep, conditional use | Cross-host project records; native search/code/git first, no claim of model superiority |
| Deterministic wiki | Keep as optional | Reproducible rendering and source freshness; it is not a semantic design reviewer |
| Improvement comparator | Keep as optional | Fixed artifacts, regression/resource gates and explicit decisions; EGM does not supply this contract |
| Generic design-review / brainstorming / review-loop skills | Use EGM upstream if adopted | Do not reconstruct EGM under OAW names or retain retired v1 reviewers just to increase skill count |
| EGM packaging | Whole official plugin | Skills depend on personas and document standards; copying seven SKILL files breaks those dependencies |
| Mandatory EGM on routine fixes | Do not add | Evaluate where design review changes outcomes; avoid imposing a costly universal ceremony |
| Catalog/scout/monitor UI and automatic absorption | Defer | Pilot the direct upstream plugin first; a registry and animation do not prove improvement |
| Universal byte limit or keyword “security” verdict | Drop as an acceptance rule | Use actual host limits and inspect actions/capabilities; keyword presence/absence is not a safety proof |

EGM contains seven skills and nine agent definitions, **not nine reviewer
personas**: the latter includes the bootstrap orchestrator and synthesizer.
Its design review requires fresh isolated reviewer contexts; same-context
self-critique must not be labeled equivalent.
[Composition and host behavior](https://github.com/google/elephant-goldfish-model/blob/f0ba151b252c9abf1318d9fe857a43265d06de89/docs/harnesses.md).

## Smallest useful next experiment

1. Fix an EGM commit and establish installed-bundle identity. Use its complete
   official plugin; keep host/model permissions constant. No new catalog runtime.
2. Pre-register outcomes and budgets. Compare A native, B native + upstream EGM,
   C native + the same EGM + only the relevant OAW evidence features. Give all
   arms the same task/source access; include C without OAW's extra guidance.
3. Use protocol scenarios for B/C interoperability. Use blinded seeded defects
   and false positives for quality. Publish all repeats and separate per-host
   results. Failed or missing runs count; regex compliance is not a quality win.
4. Retain an OAW component only when its ablation earns its cost. If B is better
   than C, remove the interfering OAW component. If B adds no useful outcome over
   A for the target tasks, keep EGM opt-in or omit it there.

This review does not convert the local future plan into an implementation or
claim live Opus 5.5 / Sol 6.1 gains. The existing comparator is an artifact checker;
it cannot verify honest traces, independent grading or an absolute quality floor
that was never specified. Eligibility still requires independent review.
