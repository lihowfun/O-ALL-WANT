# OAW 新增 skill 的正式流程

從現在起，OAW 每次加入 skill（下文叫「食物」）都走這一條流程。流程只根據 owner 決定 D1–D19（索引在最後）。網頁上的消化系統動畫、`catalog.py menu` 和 `oaw_status.py` 畫的是同一張站別表（`scripts/catalog_core.py` 的 `PIPELINE_STAGES`），讀同一份 `.oaw/catalog/view.json`。

食物有兩種：GitHub repo，和研究論文（arXiv 論文或本機 PDF）。兩種都走同一條流程；論文和 repo 不同的地方寫在第 1、2、3、4、8 站。

每一站和它的每個細項都標明今天的狀態：

- **自動**：原型 v0 已經自己會做，不用你啟動。
- **需要你**：要 owner 決定或啟動。系統不會替你決定。
- **部分自動**：一部分自動，其餘需要你或還在規劃中。
- **規劃中**：屬於這個流程，但還沒自動化。畫面上畫出來、標「規劃中」、沒有按鈕，也不會被當成已經做過。

完整指令見 [CLI Reference](CLI_Reference.md#skill-catalog-prototype-v0)。

## D21 精簡流程（2026-11-04 起）

owner 覺得原本的流程太慢、要你審的步驟太多（2026-11-03 那一輪：約 20 個要 owner 處理的步驟、3 次修訂、3 輪 Goldfish，吸收 0 個），所以改用下面的流程。它取代逐批核准（D14、PRE-08），下面九站的規則照舊，只有「誰要動手」變了。

| 步驟 | 誰 | 做什麼 |
|---|---|---|
| 入口 | 你 | 貼 repo 或 arXiv 論文網址，或在每週偵查清單上勾選 |
| 快篩 | 自動 | 每樣食物最多挑 3 個最值得的單位；沒挑到的留在候選池，寫一行理由，不再分析，也不設計付費計畫 |
| 實作 | 自動 | 寫成程式和測試，gate 必須通過；程式和測試就是紀錄，不另寫多份提案文件 |
| 盲審 | 自動 | 一輪零上下文 Goldfish 審程式 diff 和測試（D15 的 recipe）；Elephant 處理發現，只有 Elephant 不接受的 blocker 才交給你 |
| 分級 | 自動 | **A**：只改機制、不碰模型會讀的文字、不執行食物程式、可還原 → 自動吸收（D17 允許靜態證據）<br>**B**：模型會讀的文字 → 在 D13 常設預算內自動跑 A/B，齊平以上才吸收；預算不夠就排隊<br>**C**：會執行食物程式、新增執行期相依、需要常設決定沒涵蓋的授權或 CLI 選擇、移除既有 skill、超出預算 → 問你 |
| 版本 | 你 | 每個版本一頁：多了什麼、和預設比、怎麼還原；你 merge PR |

- D14 的常設選擇（授權路線、CLI 結束碼、release 目標、排出清單）視為政策，涵蓋到的項目不再另外問。
- D16：「和單吃食物比：未測」的標示保留；快篩時不再設計底線組。
- 你的例行動作只有兩個：入口和版本。
- 原型 v0 還沒照 D21 改：網頁和選單的第 8 站「核准」仍然要你勾選；A／B／C 自動分級是規劃中（見「原型 v0 還沒做的事」）。

## 流程

```text
每週偵查 → 相關性過濾 → 你勾選 ─┐
                               ├→ 1 入口 → 2 封存 → 3 靜態 → 4 計畫 → 5 盲審 → 6 實測 → 7 分流 → 8 核准 → 9 版本
你點名（可批次，重複的合併）─────┘
```

| 站 | 做什麼 | 決定 | 今天 |
|---|---|---|---|
| 1 入口（含兩條入口） | 你按「立即偵查」→ 相關性過濾 → 你勾選；或你直接點名（repo 或論文）。你勾選或點名就是同意試吃：同一個 repo、同一篇論文只收一次，接著立刻免費試吃 | D4 | 部分自動：偵查要你每週按一次（沒有排程）；過濾、去重、送去試吃：自動；勾選、點名：需要你 |
| 2 封存 | repo 固定在一個 pinned SHA、論文固定在 arXiv 版本＋sha256，唯讀封存在專案外的 `LAB_HOME`，絕不執行 | D7 | 自動 |
| 3 靜態 | 免費靜態檢查，把食物拆成成分；靜態規則只舉旗 | D5、D7 | 部分自動：檢查和拆 repo 的成分自動；論文的成分要 Elephant 拆（規劃中）；高嚴重度旗標的分流需要你 |
| 4 計畫 | 系統依證據擬測試計畫；Elephant 依紀錄的決定擬吸收提案 | D10、D11 | 部分自動：系統測試計畫自動；Elephant 提案規劃中（今天只能匯入歷史紀錄） |
| 5 盲審 | Goldfish 在驗證過的零脈絡下盲審我們的草稿，Elephant 解決發現 | D10、D15 | 規劃中 |
| 6 實測 | 在常設政策內由便宜到貴跑測試：離線整合 T1、沙箱試跑 TX、行為 A/B、整合檢查 T4、齊平底線 P | D11、D13 | 規劃中 |
| 7 分流 | 每個成分判定吸收／排掉／暫留，附原因和證據等級；套用第 6 站整合檢查和齊平底線的關口 | D2、D5、D16、D17、D18 | 部分自動：成分判定自動（只有靜態量測）；關口和 D18 的規劃欄位：規劃中 |
| 8 核准 | 你決定吸收哪些成分 | D7、D11 | 需要你 |
| 9 版本 | 每次吸收或移除都產生 `2.0.0+build.N.<hash7>`，可一鍵線性還原，列出和預設比的效果與證據等級；任何 skill（含 EGM）都能移除 | D3、D6、D12、D14 | 部分自動：版本、還原點、和預設比、附授權檔和出處說明：自動；還原、移除、加回：需要你；每版引用清單、release 目標：規劃中 |

站別的狀態符號：`●` 完成、`◐` 部分完成（這一站有規劃中的細項還沒跑，所以不畫成完成）、`◉` 目前、`⊗` 卡住、`⊖` 已移除、`○` 還沒到、`┄` 規劃中、`–` 不需要。

## 每一站的規則

### 1 入口（D4）

- **每週偵查**只偵測、累積候選。**沒有排程**：你每週按一次「立即偵查」（或執行 `catalog.py scout`）。偵查依更新時間搜尋最近 7 天推送的 repo，所以漏掉的一週，那週推送、之後沒再更新的 repo 就不會再被搜到。
- 搜尋依更新時間排序、一頁一頁抓（每個查詢最多 3 頁、每頁 100 個）；超過的部分記成「沒抓到」的數量，截斷看的是時間，絕不是星數。相關性過濾不經審查就丟掉和 coding-agent skill／harness 無關的 repo（例如影片工具）。星數只決定候選清單的排序，不是品質。
- 每週由你勾選要試哪些。沒有你勾選，什麼都不會進封存或消化。
- **你點名**：你直接給 repo 或論文。可以一次給很多個；同一個 repo 寫兩次（大小寫、`.git`、結尾斜線、SSH 或 tree 網址）只收一次。
- **論文的寫法**：`arXiv:2606.03979`、`https://arxiv.org/abs/2606.03979v2`、`https://arxiv.org/pdf/2606.03979v2.pdf`（可以不寫 `https://`），舊式編號（`hep-th/9901001`）也可以；本機論文寫 `file:///…/x.pdf`。同一篇論文的不同版本（v1、v2）是同一樣食物，只收一次；你寫的版本會記下來，沒寫就在試吃時固定最新版。其他網頁和 DOI 還不收（規劃中）。
- **你勾選或點名就是 D4 的確認**：確認後系統立刻免費試吃（第 2、3 站），不再逐樣問你。網頁的「送去試吃」、CLI 的 `add` 和 `scout pick` 都是這樣；只想登記、先不試吃，CLI 加 `--no-taste`。

### 2 封存（D7）

- 不會自動安裝或套用任何東西。
- 抓取固定在一個 pinned SHA（hardened git fetch：不跑 hooks、不 checkout、只收 https 和 `file://`；沒有 git 時改用 codeload tarball，標 `unverified-against-commit`）。
- 快照封存成 `LAB_HOME` 裡的唯讀 tar，在專案外；只在記憶體裡讀，不解壓、不 import、不執行。
- **論文**：只用 https 抓兩樣東西：arXiv 的 OAI-PMH 中繼資料（`arXivRaw`：標題、作者、摘要、授權網址、版本清單）和固定版本的 PDF（`https://arxiv.org/pdf/<編號>v<N>`；沒指定版本就固定最新版）。轉址也只能到 https 的 arXiv；有時間上限（60 秒）和大小上限（中繼資料 2 MB、PDF 50 MB）。PDF 只檢查開頭是不是 `%PDF-`、算 sha256，不解析、不顯示、不執行。PDF 和一份 `metadata.json`（記每個檔案的 sha256，沒有時間戳記）一起封存成唯讀 tar，固定在「arXiv 版本＋內容 hash」，完整性標 `sha256-recorded`（arXiv 沒有可以驗證的 hash，只記下收到的內容）。本機 PDF 一樣封存，中繼資料只來自檔案本身（沒有標題、作者、版本、授權）。

### 3 靜態（D5、D7）

- 免費 T0 檢查：檔案角色、授權、宣告的 hooks／MCP server／腳本、旗標，再把食物拆成成分（skill、hook set、MCP server、腳本、manifest、指示檔、文件）。
- 靜態規則只舉旗，不判有毒。高嚴重度旗標讓食物變成「有疑慮」，帶旗標的成分在你分流之前一律暫留；只有你分流成「確認有毒」才是有毒，那個成分才排掉。
- 分流成良性或過敏原要確認碼，只能在互動式終端機做（見「確認碼怎麼用」）。網頁在這一站顯示可以複製的完整 `menu` 指令。
- 掃描規則更新後，舊的試吃紀錄要用新規則再試吃一次（免費），才能吸收。
- **論文**：靜態紀錄只記標題、作者、arXiv 版本和日期、摘要長度（摘要原文留在 `LAB_HOME`，不進專案）和授權；hooks、MCP、腳本的檢查不適用。授權規則：CC BY、CC BY-SA、CC0 → 原文可以引用，但要附出處；其他（包括 arXiv 的 non-exclusive distribution 授權和不明的授權）→ 舉資訊旗標 `P-LIC`「只取想法：重新實作，不複製原文」。資訊旗標不用分流，也不擋任何東西。
- **論文的成分 v0 拆不出來**：拆論文要模型，所以要等 Elephant（規劃中），或匯入已有的消化紀錄；系統不會自己編成分。試吃完的論文停在這一站（`◉`），食物卡和計畫都寫明這一點。

### 4 計畫（D10、D11）

- 系統決定每樣食物怎麼吃，不是你：系統挑最便宜、又能分辨營養、沒營養和有毒的測試，排在前面。
- Elephant（完整專案脈絡，來自紀錄的決定）擬吸收提案，Goldfish 盲審（第 5 站）。
- 今天：`plan` 依證據自動產生系統測試計畫和 token 預估，每一步標它屬於 D13 的第幾階段和要哪一級沙箱。Elephant 的提案還是規劃中：只能匯入已經做好的紀錄（`import-report`），標成歷史證據，不計入任何判定。
- **論文的消化紀錄**也能匯入：`components.json`（`food_kind: paper`，每個單位用 `what` 描述）、`goldfish-*.json`、`skeptic.json`，以及 `digest.md`、`elephant-draft.md`、`elephant-final.md`、`extract.md`（記 sha256 和章節標題）。單位照紀錄的分流計數（例如 arXiv 2606.03979：16 個單位，吸收 2、暫留 3、排掉 11），一樣只是歷史證據。食物還沒登記時，系統依紀錄裡的 arXiv 編號登記，並固定在紀錄消化的那個版本；匯入不連網。

### 5 盲審（D10、D15）

- Goldfish 盲審的是**我們的草稿**：測試計畫、吸收提案、backlog 合成，以及每個合併出來的項目。只審食物本身不能取代。
- 零脈絡要驗證，不能假設：每隻 Goldfish 用固定 recipe 啟動，argv 和 init event 都顯示沒有工具、skill、plugin、MCP server 或繼承的設定。每份 Goldfish 紀錄寫明啟動方式、host 版本、繼承的脈絡和 init event 檢查。
- Elephant 解決 Goldfish 的發現，再交給你。
- 今天：規劃中。匯入的 Goldfish 紀錄只顯示成歷史證據，標「零脈絡未驗證」；紀錄沒寫的啟動欄位顯示「未記錄」。

### 6 實測（D11、D13）

- 常設政策只設定一次。之後系統在政策內自己跑免費和付費測試、回報結果，不逐樣問你；只有測試會超出政策時才問。
- 由便宜到貴：每個暫留都先跑免費的 Stage 0（D17），最便宜、還能分辨的測試先做。
- 這一站的測試：
  - **離線整合 T1**：名稱碰撞、doctor／migrate 往返。
  - **沙箱試跑 TX**：會執行食物的成分只在可拋棄沙箱（level 2）跑。
  - **行為 A/B**：模型面向的文字（skill、模板、啟動文字）要過 A/B 才能吸收（D17）。
  - **整合檢查 T4**：對現有配方的退步、觸發衝突、context 預算、指示衝突。
  - **齊平底線 P**（D2、D16）：每樣測過的食物，計畫都包含「OAW 吃完」對「單吃食物」（C ≥ B）。
- 常設政策 PRE-01（D13）：
  - 每樣食物 Stage 0/1 上限 10M logical tokens；Stage 2、第二個 host 或超過上限都要先問你。
  - 消化系統本身的開銷（Goldfish 審查、探測、fixture）每輪上限 10M。
  - 沙箱 level 1：這台機器上的專案副本，host 設定目錄改到別處；只給不執行食物程式碼的 run。
  - 沙箱 level 2：可拋棄的 Linux container 或 VM，每次試跑後銷毀；凡是執行食物程式碼、安裝任何東西、可能讀到作業系統憑證庫的 run 都要 level 2（Windows 上改 HOME 隔離不了 `USERPROFILE` 或 Credential Manager）。沒有 level 2 的機器，這類 run 一律暫留。
  - 試跑預設不給 API key；只有你自己建立專用、有上限、用完撤銷的 key 才給。Goldfish run 用可拋棄的設定目錄。
  - 網路只開 model provider API；level 2 可以短暫開 PyPI／GitHub 抓相依套件。
  - Codex 的一半在你登入 Codex CLI 之前一律記成「未測」。
  - 共用 baseline 的 A/B 成本平分給用到它的食物；candidate arm 算在它測的那樣食物上。
- 今天：規劃中。付費測試、沙箱試跑、T1、T4、P 都還沒實作；`plan` 只列出計畫和預估花費，「實測（依常設政策）」按鈕是停用的。計畫的每一步標 D13 階段：T0、T1、人工分流是第 0 階段；TX 和 A/B 冒煙是第 1 階段；T4、P、完整 A/B 是第 2 階段，一律先問你；Goldfish 審查算消化系統開銷。和每樣食物上限比的只有第 0/1 階段；TX 標沙箱 level 2。
- **`policy set` 還沒有照 PRE-01 編碼**：它存每樣食物上限、一個每週上限（D13 沒有這個上限）和一組自選的試跑條件；沒有每輪開銷上限，也沒有 level 1／level 2 的分級。PRE-01 是現行政策，請照上面的規則讀計畫；`policy set` 改成 PRE-01 的形狀是規劃中。

### 7 分流（D2、D5、D16、D17、D18）

- 每樣食物都先測過才判定。判定以成分為單位，「拉肚子」很少是整樣：
  - 🟢 **吸收**：今天是照原樣複製 skill 文字（見第 9 站）；D5 要的「重新實作成一個具名的 OAW 部件」還沒做。
  - 🔴 **排掉**：附原因和證據。只排掉有害的部分。依 OAW 原則的排掉（套件清單、第二份常駐指示檔、二進位檔）是最終的；你確認有毒的成分也排掉。
  - 🟡 **暫留**：寫明缺哪個測試。
- **模型面向的文字一律暫留到 A/B 跑過（D17）**：skill、模板、啟動文字和它的機制拆開；文字要有經同意的行為 A/B（有增益、過齊平底線、而且點名涵蓋這個成分）才算數，機制可以用靜態證據出貨。通過靜態檢查的純文字 skill（`X0`）標「暫留：缺行為 A/B（靜態檢查通過）」，不是吸收。會執行食物的步驟自動暫留。
- 每一行都標證據等級：實測（measured）、靜態量測（static-measured）、未量測（not measured）。
- **D18**：還沒建的項目寫「未量測（規劃：<等級>）」，規劃的等級放在另一欄，絕不顯示成目前的等級。今天：規劃中（還沒有這個欄位）。
- **關口**：第 6 站的整合檢查（T4）和齊平底線（P）跑過之後，這一站用它們的結果判定：整合會傷到現有配方是「拉肚子」，實測變差是「變差」，只有實測贏過食物本身才能叫「進化」；沒有對照證據就寫「齊平，未宣稱改善」或「尚未證明」。跑之前一律標「和單吃食物比：未測」。
- 今天：成分判定由 `catalog_core.derive()` 自動算出，但只有靜態量測；關口規劃中。所以這一站在流程上畫成 `◐` 部分完成，不是 `●`。

### 8 核准（D7、D11、D21）

- D21 起：A 級自動吸收、B 級過 A/B 後自動吸收、只有 C 級才問你（見「D21 精簡流程」）。原型 v0 還沒照這個改，下面是 v0 今天的行為。
- 你決定吸收哪些成分。系統不會自動安裝或套用。
- 吸收先預覽要寫哪些檔案，你確認後才動手。只選了歷史提案時，只記成待辦（寫進決定紀錄），不改任何檔案，也不產生新版本。
- 今天：因為 D17，食物的 skill 文字要先有 A/B 才能到這一站；原型 v0 沒有 A/B，所以這一站只會出現匯入的歷史提案（記成待辦）。
- **論文永遠不走「複製文字」的吸收**：論文的想法要重新實作成 OAW 的程式和測試（D5、D21），不複製原文。`absorb` 拒絕論文的任何成分，只接受它匯入的歷史提案，而且只記成待辦。

### 9 版本（D3、D6、D12、D14）

- 每次吸收或移除都產生一個專案版本和還原點。名稱遵守 SemVer 2.0：預設 release `2.0.0`，專案組合是 build metadata `2.0.0+build.N.<hash7>`（`hash7` 是內容 hash 的前 7 碼），附一個人看得懂的標籤，寫加了或拿掉什麼。內容相同的組合沿用同一個版本。
- **吸收裝什麼**：照原樣複製 skill 資料夾裡的文字，加上食物根目錄的授權檔和 NOTICE（LICENSE、NOTICE、COPYING），再加一份 `OAW-UPSTREAM.md`，寫明來源 repo（本機 repo 只寫私有代號）、pinned commit、封存的 tree hash、複製了哪些檔案、授權，以及「沒有修改」（D14 的授權路線）。重新實作成 OAW 部件以後，這份說明要改寫成修改說明。
- 一鍵還原到任何一個舊版本：預覽 → 還原 → doctor。還原只切換 OAW 安裝層，不動專案紀錄。還原是線性的：只有移除版本，沒有逐項開關（D14）。
- 每一版都列出它有哪些 skill 和成分，以及和預設 release 比的效果，每一行一個證據等級。系統在吸收當下做這個簡單評估；品質只採計這一版裝著的食物的實測證據，沒有就寫「未量測」，絕不寫「加強」。
- 移除（D6）：任何吸收進來的 skill 都能逐專案移除，包括內建的 EGM：預覽 → 備份 → 移除，記錄原因。
- **再加回要重新測試（D6）**：
  - 吸收進來的 skill：移除後，`absorb` 和網頁都拒絕用舊的試吃紀錄再吸收；要先重新試吃（免費），再核准。食物停在第 9 站，標 `⊖` 已移除，按鈕是「再送去試吃（免費）」。
  - 用「還原到這版」把移除過的 skill 還原回來時，它會標「移除後又還原回來：要重新測試」，按鈕是「重新試吃（免費）」。
  - 內建 skill 和 EGM：`readd` 經 `oaw.py migrate` 加回，決定紀錄寫「要重新測試」，版本的品質寫「未量測」。v0 沒有可以替它們跑的測試（它們是 OAW 自己的範本，不經過試吃），所以「重新測試」今天的意思是：在有實測之前，一律當成未測。
- 引用（D3）：每個版本只引用真正用到的上游材料，並寫出用在哪裡；移除或沒採用的列出原因。今天：吸收收據記下每樣食物的 pinned commit 和 tree hash，每個吸收的 skill 資料夾帶 `OAW-UPSTREAM.md`；release 的引用在 `docs/releases/<version>-sources.json`。**每個專案版本自動列出「用在哪裡／沒採用的原因」的引用清單：規劃中。**
- release 目標（D14）：所有批次進還沒打 tag 的 `2.0.0`；`2.0.0` 先打 tag 的話，相容的新增進 `2.x`，不相容的（OAW-19、OAW-12/13、OAW-25）等 `3.0.0`。今天：`RELEASE` 固定是 `2.0.0`，切換 release 目標是規劃中。

## 怎麼操作（D8）

OAW 由 Claude Code 和 Codex 共用。網頁、終端選單和 CLI 呼叫同一套引擎、讀同一份 `view.json`、用同一套顯示規則。需要 Python 3.10+（只用標準函式庫）和 git。指令都在 OAW checkout 執行，用 `--target` 指向專案：

```bash
python3 scripts/oaw.py init --target /path/to/project       # 專案還沒裝 OAW 時先裝
python3 scripts/catalog.py ui --target /path/to/project     # 網頁：消化系統動畫，可以直接操作
python3 scripts/catalog.py menu --target /path/to/project   # 終端選單：同樣的站別和動作（Codex、沒有瀏覽器時）
python3 scripts/oaw_status.py --project /path/to/project    # 只看，不做任何動作
```

### 網頁（`catalog.py ui`）

- 只綁 `127.0.0.1`，印出並開啟 `http://127.0.0.1:<port>/#t=<通行碼>`，Ctrl+C 結束。要用印出來的完整網址開，少了 `#t=…` 頁面會拒絕連線。`--no-browser` 只印網址，`--port N` 指定埠號。
- 主畫面就是流程：上面兩個入口匯進「入口」，下面每樣食物一條軌道，九個站由左到右；窄螢幕（手機、直放的平板、半個螢幕）改成每樣食物一張卡、由上往下，不會左右捲動，每一站都標自動、部分自動、需要你或規劃中。每一站的標題寫著它是哪一種；「每一站在做什麼」可以展開看每一站的細項。
- 每樣食物是一個圖示，停在它目前的站；判定出來後，圖示上用顏色點標出每個成分（🟢 吸收、🔴 排掉、🟡 暫留）。重新整理後站別變了，圖示會滑到新的站（系統設定「減少動態效果」時直接跳過去）。試吃進行中，圖示會跟著 `status.json` 停在封存或靜態，試吃結束、新的 `view.json` 讀進來之後才移到結果的那一站，不會先跳回入口；站別標題的「N 樣在這裡」也跟著圖示算。
- 這一站能做的動作，就是圖示下面的按鈕：
  - 入口：送去試吃、忘掉這樣食物
  - 封存（試吃失敗）：再送去試吃
  - 靜態：規則更新時「用新規則再試吃（免費）」；有高嚴重度旗標時，圖示下顯示可以複製的完整 `menu` 指令（確認碼只在終端），網頁上沒有分流按鈕
  - 計畫：看計畫（食物過了這一站才有）；「匯入紀錄」匯入 Elephant／Goldfish 紀錄
  - 分流：忘掉這樣食物（成分都暫留或排掉時）
  - 核准：吸收選中的成分…（勾選成分 → 預覽 → 確認）、忘掉這樣食物
  - 版本：移除；成分被還原掉時「還原到這版」；移除後「再送去試吃（免費）」
- 「忘掉這樣食物」會刪掉它的登記和證據摘要（決定紀錄保留），和成分判定的「排掉」不是同一件事。
- 盲審和實測標「規劃中」，畫成虛線，沒有按鈕；食物會被畫成「經過」它們，但不會被當成已經做過。
- 點食物名稱或圖示打開食物卡（成分、旗標、判定依據、計畫、Elephant／Goldfish 紀錄）。點「版本」站的「版本與 skill」跳到「我的 OAW」：目前版本、skill 清單（可以移除單一 skill 或整組 EGM、加回）、和預設比的效果、版本時間線（每一版都能還原）、常設預算。窄螢幕沒有站別標題列，這兩個按鈕放在流程上方。
- 試吃完成的提示依結果上色：有疑慮是琥珀色，未測是灰色，有毒是紅色；只有全部實測營養才是綠色。
- 還沒有食物時，畫面是空的流程（窄螢幕把九站由上往下列出）、兩個入口和一句怎麼加第一樣食物。

### 終端選單（`catalog.py menu`）

- 每次回到主畫面都先印出同一張站別表，一樣食物一行，例如：

  ```text
  sweet-notes  入口 ● 封存 ● 靜態 ● 計畫 ◐ 盲審 ┄ 實測 ┄ 分流 ◉ 核准 ○ 版本 ○  暫留 2 個成分（1 個 skill 文字缺行為 A/B，D17）：…
  ```

  `oaw_status.py` 印的是同一張表。
- 下面用字母列出每樣食物這一站能做的動作（和網頁的按鈕一樣，例如 `a. sweet-notes · 分流 · 忘掉這樣食物`），輸入字母就執行；需要確認碼的分流旗標也在這裡。不是互動式終端機時，分流畫面先說明只能「確認有毒」，不會先問原因再拒絕。分流畫面只列高、中嚴重度的旗標，並寫出有幾個低嚴重度旗標不需分流。
- 數字選項 1–13 是各個畫面，名稱前面標它屬於哪一站：我的 OAW、你點名、每週偵查、食物卡、核准（吸收）、移除 skill／EGM、看計畫、匯入紀錄、版本時間線／還原、重新評估、常設預算（版本）、分流旗標、加回 EGM／內建 skill。0 離開。不需要 curses。

### CLI

| 站 | 指令 |
|---|---|
| 入口 | `add URL [URL ...] [--no-taste]`、`scout`、`scout list`、`scout pick N [N ...] [--no-taste]`、`forget FOOD [--apply]` |
| 封存、靜態 | `taste FOOD`、`show FOOD`、`triage FOOD FLAG --benign\|--allergen\|--confirm-toxic --reason TEXT` |
| 計畫 | `plan FOOD`、`import-report FOOD DIR`、`policy show`、`policy set ...` |
| 核准 | `absorb FOOD --components ID[,ID] [--apply]` |
| 版本 | `builds`、`restore BUILD [--apply]`、`effect`、`remove SKILL\|egm --reason TEXT [--apply]`、`remove FOOD --food --reason TEXT [--apply]`、`readd SKILL\|egm --reason TEXT [--apply]` |
| 全部 | `view`（重算 `view.json`）、`list` |

`add` 和 `scout pick` 是你的確認：登記後立刻免費試吃，`--no-taste` 只登記。`absorb`、`remove`、`readd`、`restore`、`forget` 沒加 `--apply` 時只預覽；`remove`、`readd` 套用時一定要 `--reason`。每個指令都可以加 `--json`。結束碼依 D14 的 CLI 約定：`0` 完成、`2` 拒絕或失敗（批次裡有食物試吃失敗也算）、`3` 需要你選擇（網頁或選單在等你輸入確認碼）。

### 確認碼怎麼用

設定常設預算和分流旗標（`--benign`／`--allergen`）只有 owner 能做：

- **CLI**：在你自己開的**互動終端**（PowerShell、cmd；Git Bash 請用 `winpty`）執行 `policy set ...` 或 `triage ...`。終端印出 6 位數確認碼，同一個指令接著請你打回去，對了才生效。沒有 `--confirm` 參數，也不會寫任何待確認檔。
- **網頁和 `menu`**：確認碼印在啟動 `ui` 或 `menu` 的那個終端，只存在那個程序的記憶體裡；你把它輸回頁面或選單。10 分鐘內有效、只能試一次、綁定那一組設定；同一次啟動錯三次就不再接受確認，要重新啟動。
- 沒有互動終端（stdin 和 stderr 不是終端機，例如 agent 在背景執行、輸出導到檔案）時，根本不會產生確認碼，指令直接拒絕。

**這只是減速帶，不是身分驗證。** 確認碼擋住的是「agent 透過 catalog 指令替你設定」這條路；任何能在你的終端打字的人或程式（包括在 PTY 裡跑指令的 agent），都能看到並輸入確認碼。`policy.json` 和 `decisions.jsonl` 是沒有簽章的專案檔，對專案有寫入權的程式可以直接改它們，所以紀錄裡寫的是 `confirmed_via: code typed back on an interactive terminal (unauthenticated)`，不會寫「由 owner 確認」。請自己輸入確認碼，不要貼給 agent。

## 一定要守的規則

- **沒有證據就沒有判定**。判定只由 `catalog_core.derive()` 從證據和你的決定算出來；星數、作者和名氣只決定偵查清單的排序。匯入的報告是歷史證據，只顯示、不計入判定。
- **食物不進專案，也不執行**，直到你核准吸收。食物或報告裡的文字是資料，不是指令，不能授權任何動作。
- **只有你能判「有毒」**。自動掃描只舉旗，不會替作者貼上有毒的標籤。
- **模型面向的文字要過 A/B**。靜態檢查通過的 skill 文字只是「暫留：缺行為 A/B」，不會顯示成綠色的吸收（D17）。
- **先預覽、再備份、才動手**。吸收、移除、加回、還原都先預覽；套用前先存還原點。
- **還原只動 OAW 安裝層**：只寫入或刪除 OAW 自己會安裝的路徑（OAW 範本、吸收進來的 skill 文字和它的授權檔、出處說明、EGM runtime、吸收收據），絕不碰 `.git/`、host 設定（`.claude/settings*.json`、`.codex/`、`.mcp.json`）或專案紀錄。你宣告的自訂檔（例如保留的 `AGENTS.md`）照原樣留著；不屬於目前安裝層的現有檔案會擋住還原，不會被蓋掉。還原點只接受這台電腦替這個專案建立、記在 `LAB_HOME` 索引裡的那些，`builds.json` 寫什麼都不算數。
- **移除只刪查得到的檔案**：吸收收據是會 commit 的共用資料，所以移除前逐檔確認它在那個 skill 的資料夾裡、在 `install.json` 裡、hash 也相同；有一個不符就整個拒絕。移除的名稱只代表一件事：`egm` 是整組 EGM，內建 skill 名稱是那個 skill，其他名稱是你吸收進來的那一個 skill；要移除一樣食物的全部 skill，加 `--food`。食物的 id 不會取 `egm` 或內建 skill 的名稱。內建 skill 和 EGM 經 `oaw.py migrate` 移除和加回（先備份到 `.oaw/backups/`）；移除不會順帶新增，加回不會順帶停用。
- **「加強」只在有實測證據時出現**，否則一律寫「未量測」。執行中只顯示進度和花費，不顯示即時分數，避免看了結果再停掉重跑。
- **網頁只給你自己用**：只綁 `127.0.0.1`，每次啟動換一個通行碼，拒絕其他 Host 和跨站請求，動作只接受 JSON POST，一次只跑一個動作。食物裡的文字一律當純文字顯示，不渲染食物附帶的 HTML、SVG 或圖片。

## 原型 v0 還沒做的事

- **D21 的自動分級還沒進原型**：網頁、選單和 `catalog.py` 的第 8 站仍然要你勾選；A 級自動吸收、B 級 A/B 後自動吸收、只有 C 級問你，這三條都是規劃中。D21 目前用在 OAW 自己吃食物（寫成 `claude/oaw-2` 上的程式），還沒用在你專案裡的 skill 吸收。
- **盲審、實測、整合檢查、齊平底線都是規劃中**：只列計畫和預估花費。所以 v0 不會出現「營養」或「進化」，品質一律顯示「未量測」，每樣測過的食物都標「和單吃食物比：未測」。
- **沒有行為 A/B，所以食物的 skill 都不會被吸收（D17）**：吸收、版本、還原、移除的機制都做好了，也有測試，但真正的食物要等 A/B runner 做出來，才能走到第 8 站。今天走得到第 8、9 站的是匯入的歷史提案（記成待辦），以及內建 skill 和 EGM 的移除、加回。
- **吸收是照原樣複製**：還沒重新實作成具名的 OAW 部件（D5）。
- **只吸收純文字 skill**：hooks、MCP server、腳本、manifest 等成分只記成待辦，不安裝，也不在你的電腦上執行。SKILL.md（或它附帶的說明檔）裡只要叫 agent 執行指令（程式碼區塊、行內指令、「執行 `…`」），或碰到任何旗標規則（網路、家目錄、`curl | sh`…），就算 `X1-inline`，要在可拋棄環境測過才能吸收；旗標分流成良性也一樣。
- **D18 的規劃等級欄位、每版的引用清單（D3）、release 目標切換（D14）、Elephant 提案（D10）、`policy set` 的 PRE-01 形狀（D13）**：都還沒做。
- **來源只限 github.com repo、arXiv 論文，以及本機 `file://` repo 或 PDF**。其他網頁和 DOI 是規劃中。私有 repo 抓不到，因為 GitHub token 不會交給 git；`GITHUB_TOKEN` 只用在偵查搜尋。試吃抓整份 depth-1 快照（有大小上限）。
- **Elephant 替論文拆成分是規劃中**：今天論文的成分只能從匯入的消化紀錄來（歷史證據），所以論文不會出現在「靜態量測」的成分判定裡。論文的計畫沿用 repo 的測試步驟，還沒有專給論文的計畫（例如「重新實作後跑測試」）。
- **偵查沒有排程**：要你每週按一次。
- **分流旗標不在網頁上**：有高嚴重度旗標的食物，網頁顯示 `menu` 的完整指令。
- hash 鏈事件紀錄、`catalog.py check` 重算 gate、`install.json` schema 2 都還沒做。

### 已知問題（還沒修）

- **Claude mod 原型**（`oaw-digest-monitor`，不在這個 repo）還沒讀 `status.json` 的可選欄位 `headline`、`stop_reason`：免費試吃完成時它會顯示「完成 · 進行中」，試吃失敗時會一直顯示進行中。`oaw_status.py`、`menu` 和網頁顯示的是正確的「最近一次試吃 … 未測」或「已停止：原因」。
- **吸收的 skill 只裝到吸收當時的 host**：之後才加上第二個 host 時，畫面會標「只在 Codex／只在 Claude」，但還沒有「補裝到另一個 host」的動作，doctor 也還沒有對應的警告。要補裝，先移除再吸收一次。
- **還原寫入的 `install.json` 和那一版不完全相同時**（例如保留了你的自訂檔），結果會記成一個新的版本，而不是沿用原本的名字。

已驗證的範圍：gate 和端到端 smoke 只在 Windows／Python 3.13 跑過，POSIX 還沒實際跑。

| `plans/<food>.json` | 系統的測試計畫和預估 |
| `policy.json` | 常設預算（設定後才有） |
| `scout.json` | 偵查候選、被濾掉的數量、每次偵查的時間範圍和沒抓到的數量（偵查後才有） |
| `builds.json` | 版本清單、每版的 skill 和成分、時間線 |
| `absorbed/<food>.json` | 吸收收據：裝了哪些檔案和它們的 hash |
| `effect.json`、`view.json`、`status.json` | 衍生檔，可以隨時重算（`effect`、`view`） |

系統會產生 `.oaw/catalog/.gitignore`，只讓 `builds.json` 和 `absorbed/*.json` 可以 commit，其他資料只留在這台電腦。

### 專案外：`LAB_HOME`

| 系統 | 預設位置 |
|---|---|
| Windows | `%LOCALAPPDATA%\oaw\lab` |
| macOS | `~/Library/Application Support/oaw/lab` |
| Linux | `$XDG_DATA_HOME/oaw/lab`（預設 `~/.local/share/oaw/lab`） |

可以用環境變數 `OAW_LAB_HOME` 改到別的目錄，但它必須在專案外，也不能在 OAW checkout 裡，否則指令會拒絕。

| 路徑 | 內容 |
|---|---|
| `foods/<food>/<commit>/source.tar`、`inventory.json` | 封存的食物快照（唯讀）和檔案清單；論文是 `foods/<food>/<版本>-<hash>/`，tar 裡只有 `paper.pdf` 和 `metadata.json` |
| `builds/<專案代碼>/<hash>.tar` | 每個版本的還原點 |
| `builds/<專案代碼>/index.json` | 這台電腦替這個專案建立過的還原點（還原只接受這裡列的） |

還原點只存在建立它的那台電腦的 `LAB_HOME`。刪掉 `builds/` 就不能再還原到那些版本；隊友 clone 專案後看得到 `builds.json`，但不能用你的還原點。
