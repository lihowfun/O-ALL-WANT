# OAW v2.0.0 execution plan

Status: implementation validated locally, 2026-10-28. Delivery is a draft pull request for an independent Claude Code review. Do not merge, tag, or publish a release.

## Outcome

Turn OAW into a small, portable project knowledge and verification toolkit around native coding agents. Claude Code and Codex retain ownership of their agent loops, sessions, compaction, personal memories, permissions, and skill discovery. v2.0.0 is a breaking change to installation defaults and skill layout, not a claim of measured model superiority.

## Accepted scope

| Workstream | Deliverable | Acceptance |
|---|---|---|
| Core reliability | Confined topic paths; complete locked read-modify-write; correct freshness; idempotent annotation rebuild; relative-link rebasing; truthful CLI exits | Regression fixtures reproduce reviewed failures before the fix and pass afterwards; real concurrent writers retain every entry |
| Bounded recall | Record-oriented search with JSON, source locations, truncation, and continuation | Long and adjacent matches cannot bypass the output budget; cursors paginate without silent loss |
| Native integration | Short AGENTS.md, thin Claude adapter, standard SKILL.md packages | Native skill schema passes; no mandatory startup reads, session reports, memory writes, step-count reviews, or custom trigger resolver |

| Verification | One local/CI gate with focused regression tests and complete generated example comparison | Broken skills, example content drift, unrelated negative-test crashes, and invalid installer outcomes fail the gate |
| Version documentation | Version 2.0.0 proposed, changelog, migration guide, refreshed EN/ZH README and CLI docs | Added/changed/removed behavior and old-install preservation are explicit; historical claims are labeled |

## Installation contract

`python scripts/oaw.py init --target PROJECT [--profile minimal|knowledge] [--with-improve]`

- Minimal: short project instructions, Claude compatibility import, the evidence skill, context_hub and its common helper. No placeholder document collection or automatic memory creation.
- Knowledge: adds the wiki renderer, wiki skill, validator, and empty source/wiki stubs.
- `--with-improve`: adds the optional improvement CLI and skill. It does not enable background jobs or force a review after tasks.
- Framework upgrades are `migrate --target PROJECT` previews; only `--apply` writes. Known unmodified managed files can update. Custom conflicts become proposals and require review. Mutable project records are never template-managed.
- Host support and enabled settings are distinct. Doctor reports uncertainty and does not silently change Claude/Codex configuration.
- `--host codex|claude|both` selects native skill paths; additions persist. Reviewed conflicts can stay project-owned with `migrate --apply --keep-custom PATH`.

## Self-improvement contract

1. Start with a reproducible failure or recurring workflow worth improving. NOACTION is a valid outcome.
2. Store a concrete candidate diff, hypothesis, target, and fixed evaluation specification.
3. Capture baseline and candidate runs on matched tasks, model/effort, host/version, environment and base snapshot. Keep execution evidence; record tokens, latency and cost.
4. Compare deterministic checks before assessing efficiency. Reject quality regressions. Insufficient or mismatched evidence is inconclusive.
5. A favorable comparison makes a candidate eligible for explicit review, never automatically applied. An accept/reject decision records its reason and evidence hashes. Applying the reviewed patch remains a separate normal development action.

The first implementation validates artifacts and compares reported measurements. It does not call paid model APIs, certify that a trace is truthful, or establish statistical superiority. Native Claude/Codex A/B runs remain a follow-up until credentials and representative tasks are available.

## Explicit exclusions

Do not merge the Hermes branch wholesale or ship its mandatory nudge/manual usage counters. Do not add a second model runtime, vector database, graph memory, background self-rewriting daemon, or unsupported claims of native feature availability. Historical v1 experiments remain history; their do-not-rerun notes are not carried forward as permanent runtime restrictions.

## Release notes outline

Added: safe init/migration/doctor, bounded evidence retrieval, native skill packages, optional improvement artifacts, meaningful regression tests.

Changed: default installation is small and native-first; project records and framework metadata are separated; generated examples and CI use the same contracts.

Removed from defaults: flat trigger-scanned skills, universal master router, placeholder state mirrors, forced memory/report workflows, evidence tier freezing, and memory/skill telemetry loops.

Fixed: path escape, concurrent memory loss, stale-date leakage, annotation growth, relative-link relocation, zero-success exits, and gate false passes.

Validation and independent review handoff: [local results](../validation/v2.0.0-local.md), [Claude Code review focus](../CLAUDE_REVIEW.md). Native model A/B experiments and live host discovery are explicitly not claimed.
