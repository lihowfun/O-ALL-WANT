## M3: permission-only fallback, no migration

1. Primary remains .agents/memory.md. Pending notes go to
   .oaw/memory-pending.md, derived from BASE_DIR. Do not copy, move, truncate,
   reconcile or delete either source; pending notes remain readable after
   primary permissions recover. No automatic merge is introduced.
2. Refuse credential-bearing notes before any write. Confine the primary and
   the fallback paths, including symlink ancestors. Keep locked_update's stable
   sidecar locks and atomic replacement for each file.
3. Try the primary write. Fall back only on OSError with EACCES, EPERM or EROFS
   (including PermissionError with a permission errno); a denied lock or temp
   creation is included. Do not fall back on invalid paths, malformed input,
   credential rejection, missing directory components blocked by a regular
   file, disk-full, generic I/O errors, timeouts, or other failures.
   A fallback failure propagates a nonzero CLI result. Report the actual path
   on success and label a fallback explicitly.
4. Both sources are read by memory recall/show, search --memory, status,
   bootstrap and legacy context lanes. Keep one shared loader and entry order.
   Missing files are empty; existing unreadable or out-of-bound sources fail
   visibly rather than disappearing from evidence.
5. Newly written entries use an ISO-8601 UTC timestamp with microseconds in the
   existing bracketed date field: ## [2026-11-13T10:00:00.000000+00:00] [TAG] ...
   Generate it inside the mutation after the destination lock is acquired.
   Preserve legacy entries byte-for-byte. Legacy YYYY-MM-DD dates are treated
   as the start of that UTC day only for ordering; do not invent time metadata.
6. Merge memory entries newest first by parsed date/time. Invalid dates sort
   last. Equal timestamps use pending before primary, then original source
   order; this is a deterministic tie break, not proof of chronology.
   Do not use file mtime: a new write to the primary must not promote all of
   its old entries above newer pending decisions. Knowledge pages follow memory
   hits in their existing filename order. Original source paths and line
   numbers remain the provenance for excerpts and index rows.
7. Supersession remains evidence, not an automatic semantic operation. Preserve
   old and new entries, including explicit "supersedes" language. Return newer
   matching notes first; do not silently delete, deduplicate or declare one
   conclusion authoritative. Documentation must say that dates and lexical
   matches cannot infer supersession when the replacement does not match the
   query. Query the relevant topic and inspect its cited source.
8. Recall snapshot identity includes both source labels, missing/present state
   and contents, plus current knowledge sources. A source addition, deletion
   or edit invalidates the cursor, even if it contains no matching note.
   Bind the new ordering semantics into the snapshot so old cursors restart.
   Preserve bounded text/JSON output and mode/query binding.
9. Readers consume per-file atomic snapshots, not a cross-file transaction.
   Concurrent writers cannot lose entries within either file. A later change
   invalidates continuation on the next call; no cross-file global write lock
   or clock-synchronization claim is introduced.

## M1/M2: coherent policy and empty recall

- Save project decisions/facts needed later and not reconstructable from code
  before the session ends; no explicit user request is required.
  Keep source/revision/scope, credential refusal, and the host/project boundary.
- Empty recall says no matching project record, then directs the caller to the
  host's available and permitted memory/history. Do not hardcode private
  transcript locations or perform host reads inside this Python tool.
- Text and JSON expose the empty-result guidance, within max_chars. Do not
  mistake truncated/paginated nonempty results for an empty search.
- Update policy and evidence skill together; document the pending-note source.

## R1/R2: native review and one code-review round

- In a Codex session, use one native fresh-context subagent; pass the relevant
  diff/new files and test command, wait for its result, and resolve findings.
  A suggested command is not an observed review event. Never use nested
  codex review for the default same-family path.
- Preserve explicitly requested cross-family review: Claude-to-Codex needs its
  separate Codex CLI instruction; Codex-to-Claude keeps its existing consented
  command. A generic native subagent must not pretend to change model family.
- Standard and deep code-review steps both have rounds=1. Text, structured
  output and skill agree. Resolve findings and run affected tests; further
  independent review is explicit, not an automatic loop. Design review is a
  separate pre-code step and is not removed.

## #18: visible literal-path audit

- Reproduce alias/canonical spelling mismatch before changing the detector.
- Recognize workspace and cohort path spellings at path boundaries; avoid
  substring exemptions for T001-other when the allowed directory is T001.
- Normalize visible literal read/list arguments so symlink/case spelling
  behaves consistently with the workspace/cohort comparisons. Keep the
  existing distinction between a read and Markdown data being written.
- This is trace auditing, not shell parsing or OS isolation. Do not claim it
  catches variable expansion, encoded paths, or every shell construct.
- Tests cover canonical and alias access, relative ancestors, workspace reads,
  sibling prefix collisions, spaces, and Markdown link data. Existing CI
  matrix remains unchanged; a Linux pass cannot stand in for macOS/Windows.
