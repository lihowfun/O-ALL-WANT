# 試吃量測規則（一頁版，D32）

吸收別人的 skill、或改 OAW 自己的預設之前，都照這一頁量。決定的出處是 `records` 分支的 `digestion-2026-11-03/ingest/DECISIONS.md`（D26、D29、D32、D35），證據在 `records/digestion-2026-11-07/validation/RESULT.md`。完整流程見 [SKILL_INTAKE.md](SKILL_INTAKE.md) 開頭的一頁版。

## 設計
- **題目**：預設 12 題各跑 1 次，把題目當成隨機樣本。原生已經接近滿分的題目要換掉。
- **出題者**：由不知道 OAW 實作的新 agent 出題，題目的 sha256 推上 `records` 之後才開跑。
- **組別**：至少要有原生和食物（官方安裝）兩組。skill 類多一組「只放 description」；量偵測能力時，加一組正對照和一組不洩題的便宜做法。
- **條件**：至少一個「食物的主場」條件；排掉之前一定要有。
- **預算**：2.0.1 發佈前每項 30M（D35），只用訂閱計費（apiKeySource 為 none）。

## 評分
- **兩家盲評**：Opus 和 Codex 各評一次，評分者看不到組別。
- **差距要兩家都成立才算**。同家族評兩次不算獨立（kappa 0.97）。
- 錯誤陳述數也只在兩家一致時才算。
- 花 0 token、或被用量上限切斷的評分算「沒跑」，不是 0 分。

## 判定（`scripts/eval_stats.py`）
- **品質**：每題算食物減原生的配對差，對題目做 bootstrap（10,000 次、seed 20261107）。

  | 類別 | 條件 |
  |---|---|
  | 更好 | 95% 區間在好的那一邊不含 0 |
  | 更差 | 95% 區間在壞的那一邊不含 0 |
  | 等價 | 90% 區間落在邊界內（TOST） |
  | 未定 | 以上都不是 |

  邊界：覆蓋率 ±0.10、每份答案的錯誤陳述 ±0.5、偵測數 ±1。
- **零變異下限**：每格只跑 1 次時，標準誤不能小於 `floor_sd × √(2/題數)`。`floor_sd` 用同一題庫、同一模型以前重複作答的合併題內標準差（`pooled_within_sd()`），寫進 PREREG。
- **合併**：一次評分內用 `quality()` 合併覆蓋率和錯誤陳述，兩家評分用 `agree()`，多個條件用 `lowest()`（最差的條件決定）。
- **成本**：每題 token 比取 log 後做 bootstrap。

  | 類別 | 條件 |
  |---|---|
  | 太貴 | 區間下界超過 1.5 倍 |
  | 比較省 | 區間上界低於 1 倍 |
  | 在上限內 | 區間上界不超過 1.5 倍 |
  | 未定 | 區間跨過 1.5 倍 |

## 結果
`eval_stats.judgment()` 產生記帳用的欄位：`quality`、`quality_class`、`cost_ratio`、`cost_ci`、`cheaper`、`grading`（`cross-family` 或 `mechanical`）、`conditions`。`catalog.py record-tasting` 會檢查判定和這些欄位一致。

| 品質 | 成本 | 結果 |
|---|---|---|
| 更好 | 不是太貴 | 進預設 |
| 更好 | 太貴 | 可選用 |
| 等價 | 比較省 | 進預設 |
| 等價 | 其他 | 可選用；太貴則排掉 |
| 未定 | 不是太貴 | 可選用（能力未定）；未定永遠不會變成預設 |
| 未定 | 太貴 | 排掉 |
| 更差 | 任何成本 | 排掉 |

不在這一頁裡的：D21 的 C 級問題（執行期相依、會執行食物程式）照舊問 owner。
