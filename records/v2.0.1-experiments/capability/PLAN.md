## 3. 組別、格、隔離

- **N（原生）**：共同工具裝好，沒有候選。PPT 的共同工具是 python-pptx、LibreOffice、Noto CJK 字型、Node；影片是 ffmpeg、ffprobe、Node、Chrome。N 跑兩次（N1、N2）。
- **S_k**：N 再加候選 k 的固定版本。
- **兩格**跟 H1 一樣：Claude Code + Opus 5.5（effort high）；Codex CLI + gpt-6.1-sol（reasoning high）。每題各組的順序照 H1 輪轉。
- **安裝樣板**：每組事先在不連網的狀態下做好一個樣板（家目錄骨架加工具目錄），整份算摘要，唯讀掛進沙箱、掛在原本的路徑。每次 run 記下實際掛載、PATH 和啟動時看到的 skill 清單。S 的清單減掉 N 的清單，必須剛好等於這個候選凍結名單上的單位；兩組共有的內建 skill 也要一樣，名單寫進凍結檔。
- **作答時的網路**：只放行兩個 CLI 登入和呼叫模型需要的連線（沙箱外一個只認白名單主機的 proxy，沙箱本身不給網路）。依賴、素材、字型都事先放進樣板；候選的自動更新關掉（例如 OfficeCLI 的背景更新檢查）。開跑前用探針確認：沙箱裡下載 npm、PyPI、GitHub 都失敗，模型呼叫正常。
- 其餘照 H1：全新工作區、全新家目錄（只掛登入檔）、評分在全新環境而且不連網、帳本（starts、attempts、rows）、中斷也算一次嘗試、每組每題最多 3 次基礎設施失敗。

## 4. 題目

- **每個領域 4 題**，由零上下文的 Codex 盲出。出題者只知道使用者要什麼成品，不知道候選是誰、也不知道組別。
- 每題附輸入素材、需求、檢查程式、一份參考成品，另外**至少兩份做法不同但合規的替代成品**，以及題目指定的反例。參考成品和檢查程式只在評分時出現，作答的 agent 看不到。
- **驗題**：參考成品和替代成品都要過；空交、只交輸入素材、每一個反例都要不過。反例至少包含：
  - PPT：文字溢出文字框、轉檔後被裁掉、被不透明圖形蓋住、重複的文字、旋轉的中文、白字白底、表格做成圖片。
  - 影片：漏字幕、剪錯點、漏淡出、左右聲道對調、漏掉旁白。
- 需求刻意放進原生容易漏的地方：PPT 是內容多到要拆頁、長中文標題、很多列的表格、可編輯的圖表、指定字級；影片是精準剪接、淡入淡出、字幕、混音。
- **校準**：Codex 格 N 跑一次，滿分的算頂到天花板、不選；不夠就請同一份 brief 的新出題者補，最多補兩次，還不夠就停下來回報 owner（照 H1 驗題 6）。

## 5. 檢查（評分程式看不到組別）

**PPT**
- python-pptx 打得開；頁數、標題、指定的文字和數字在對的頁。
- **有效字級**：順著文字、段落、形狀、版面配置、母片、佈景主題一路往上找到實際字級，再跟題目規定比。
- **看得見**：文字顏色和底色的對比要夠（3:1 以上）；空的文字框不算。
- **可編輯**：表格是表格物件、圖表是圖表物件；圖表的類型、數列值、類別標籤、單位要跟題目一致。另做一次「改一個數值或儲存格 → 存檔 → 重開 → 重新算繪」，新數值要出現在算繪結果裡。
- **溢出、裁切、遮擋**：LibreOffice 轉 PDF，用 pdftotext 取每個字的座標，對回每個文字框：框裡的字都要出現（少了就是被裁掉）、都要落在框內（容許一點誤差）和頁面內；疊在上層、不透明、蓋到字的形狀算遮擋。手造的反例偵測不穩的情況，就不宣稱驗過那一種。
- **版面只管題目明講的**，不另外加「文字框不能重疊」這種全面規則。

**影片**
- **容器**：ffprobe 讀長度（容許 1 幀）、解析度、幀率、編碼、音軌和視訊軌數。
- **剪接**：輸入素材每一幀的畫面都不一樣。把成品每一幀對回最接近的素材幀，重建剪接表，檢查片段順序和剪接點（容許 1 幀）、有沒有多出來的黑畫面。
- **淡入淡出**：淡入（淡出）區間的平均亮度要從接近全黑單調上升（下降），區間外要跟素材一致。
- **字幕**：要字幕的題目，同時要求燒進畫面和內嵌字幕軌。文字和起訖時間用字幕軌逐條核對；燒入只檢查字幕區在該出現的時間有變化、其他時間沒有。燒進畫面的字是不是對的沒有 OCR 可以驗，照實寫進限制。
- **音訊**：素材用可以分辨的訊號（旁白、配樂、音效各用不同的頻率或節奏）。逐段核對每個來源有沒有出現、時間、相對音量（容許 1 dB）、聲道，另外檢查有沒有破音。
- PSNR 只用在題目指定的畫面區域和時間窗，不做整張畫面比對。

美感不判定。PPT 的算繪圖會留下來，只當描述。P2 主打設計品質，這輪沒有量到，結論不外推到美感。

## 6. 判定

每一格、每一題，看 N1、N2、S 各自過不過：
- **新過**：S 過，N1、N2 都沒過。
- **退步**：S 沒過，N1、N2 都過了。

每一格的結果：
- **改善**：新過至少 2 題，而且沒有退步。
- **變差**：退步至少 2 題。
- **未定**：其他情況，包括平手、只差一題、三組都滿分。

兩格合併，每個候選一個結果：

| 情況 | 結果 |
|---|---|
| 至少一格改善，兩格都沒有任何退步，閒置條件通過 | 暫列可選用 |
| 任何一格變差，或閒置條件沒過 | 排掉 |
| 其他（包括一格改善、另一格有 1 題退步；兩格都未定） | 這輪未達推薦門檻 |
| 裝不起來、要金鑰、run 沒跑完 | 未完成，不判 |

- 這輪是**描述性的採用篩選**，不是證明誰比較好：4 題各跑一次，就算 4 題全贏，單尾 sign test 也只有 p = 1/16。「未達推薦門檻」不等於證明沒用。
- 三組都滿分的題目另外列出來，標「頂到天花板」。
- 「暫列可選用」的照授權決定能不能收進 OAW：MIT、Apache 可以；owner 自己的 skill 由 owner 決定。都不進預設。

## 7. 閒置條件

- **題目固定**：H1 A 類的 t01、t04（題庫順序的前兩題）。
- 每格 N 和每個 S 各跑一次，兩兩配對、順序固定。
- **啟動 token** = 每個 session 第一次呼叫模型時的輸入 token（含快取）。系統提示、工具和 skill 清單在同一組裡是固定的，所以這個數字幾乎不會變。S 不能比 N 多超過 2%。
- 兩題都要照 H1 的隱藏測試做對；紀錄裡不能有用到候選的痕跡（載入 skill 或呼叫候選的執行檔）。

## 10. 預算

- **Claude**：每個領域算一個實驗，上限 30M（D35「每個食物或實驗」；比 D41 寫的每個食物 30M 還嚴）。
  - 花費順序和停止順序：先 N1、N2，再照表格順序跑候選（P1、P2、P3；V5、V1），每個候選的閒置檢查跟在它後面。累計到 27M 自動停，沒跑到的候選記成「未完成」。
  - 估計：作答 (N1 + N2 + 3 個 S) × 4 題 = 20 次，每次約 0.5–1M，合計 10–20M；閒置 2 題 × 4 組約 2.4M；探針約 0.5M；中斷和重試另乘 1.25 倍。所有嘗試都算。
- **Codex**：用 ChatGPT 方案，不算在上限內，另外記錄。
- **磁碟**：可用空間低於 15G 就停。只清暫存的算繪檔；成品、評分結果、重現需要的資料都保留（影片壓縮保存）。
- **前置條件**：影片要用的 ffmpeg 還沒裝（2026-11-10 在使用者目錄安裝時被權限檢查擋下，等 owner 處理）。PPT 不需要 ffmpeg。
