# 第 1 次程式碼檢查的處理（2026-11-12）

Codex 判「先改再跑」，20 點。全部照改；下面是每一點改在哪裡。行號以改完的檔案為準。

| # | Codex 指出 | 怎麼改 |
|---|---|---|
| 1 | 沙箱以整個主機根目錄為底 | `cap_run.py` `sandbox()`：改成從空的根目錄開始，只掛 `SYSTEM_DIRS` 列出的系統目錄（唯讀）、工具副本、工作目錄、家目錄、該組樣板和登入檔。不再有「要遮住哪些目錄」的設定。`guard_paths()` 在每個指令開頭檢查：狀態、暫存、樣板、工具副本、本資料夾、語料、題庫、使用者家目錄都不能落在沙箱看得到的目錄裡。沙箱裡沒有 `/run`、`/var/run` 的內容；探針多一項「看得到主機 socket 就算失敗」，並記下沙箱裡看到的根目錄、`/home`、家目錄和所有 socket |
| 2 | 探針沒綁定它驗過的設定 | `probe_config()`：每筆探針記下啟動設定、proxy 程式、該組樣板、工具副本、Claude 暖機檔的摘要；`manifest --write` 逐組核對探針的摘要等於要凍結的設定，不一樣就拒絕 |
| 3 | 候選安裝內容沒在出題前鎖定 | `cmd_setup` 寫 `setup.json` 的 `lock`（計畫、brief、四支程式、H1 runner、每個樣板、工具副本的摘要）；`check_lock()` 在之後每個指令開頭核對，任何一項變了就拒絕、要換新的狀態資料夾。出題的 start 紀錄記著 lock 摘要和各候選的單位 |
| 4 | 單位數沒限制、候選掛載可以蓋掉共同工具 | `template_problems()`：單位 1 到 3 個、要有版本 pin、掛載目標要在沙箱家目錄裡、不能碰到共同工具的掛載或工作目錄或登入檔、skill 目錄下的掛載要剛好等於單位名單。P3 原本整個蓋掉共同的 site-packages，改成自己的套件放另一個路徑（共同的 site-packages 裡一行 `.pth` 把那個路徑加進 Python 路徑，每組都一樣，只有 P3 那個路徑存在） |
| 5 | 校準結果沒綁檢查器和門檻版本 | 同第 3 點的 lock：檢查器、門檻、brief、runner 在 `setup` 就鎖住，校準在這之後。每筆 run 記 `lock_sha256`、`check_sha256`；`cmd_select` 要求每筆校準結果是同一個 lock、同一支 runner、同一份題目內容，並要求每位出題者拿到的封包相同 |
| 6 | Codex 沒有執行鎖、首筆採用不是原子操作 | `cmd_run` 一開始就拿 `run-<tag>-<cell>.lock`（兩格都有，拿不到就拒絕）；寫入時在鎖裡再查一次，已有計分列就不寫第二筆。`codex_slot` 限制同一個狀態資料夾最多 2 個 Codex session 同時跑 |
| 7 | Claude 探針繞過停止線 | `claude_gate()`：所有 Claude session（探針、暖機、作答、閒置）共用同一個檢查（已花 + 預估 × 1.25 不能超過停止線），執行中也都帶剩餘額度 |
| 8 | 磁碟前置條件沒實作 | `space_gate()`：每次開跑前檢查；需要的量 = 量到的單次峰值暫存 × 2（兩格同時）＋ 剩餘 run 數 × 量到的單次保留量 ＋ 15G。量測值記在每筆 run 的 `scratch_bytes`、`kept_bytes`，選題時的量測寫進凍結檔。空間不夠回傳 8、不開跑；跑到一半遇到 ENOSPC 記成沒跑成（不算在 3 次失敗裡）並停下 |
| 9 | 有效字級漏讀段落層 | `ppt_check.py` `Sizes.runs()`：run 之後先看段落的 `a:pPr/a:defRPr`。反例 `para-big`（36）、`para-small`（9） |
| 10 | 圖表文字沒進機械檢查 | 圖表也是一個 frame（`kind == "chart"`）：單獨算繪這張圖表，取它的字詞框、字級和筆畫（字詞框內跟中位數差 64 以上的像素），再跟「整張投影片拿掉這張圖表」比可見性；套用 coverage、off-page、word-out、rotated。`c.size_min` 是圖表文字算繪後最小的字級。反例 `chart-covered`、`chart-small`、`chart-edge` |
| 11 | 改值驗證會把別的物件的變化算進來 | 每張圖表、每張表各自一份變體（只留它那一頁、只改它）；圖表要重開後值還在，而且它的範圍內、扣掉文字框以後的像素變化 ≥ 0.5%；表格要重開後儲存格是標記字，而且標記字出現在這張表的範圍內。反例：同一頁兩張圖表、兩張表 |
| 12 | 表格沒有逐儲存格的框界 | 每個儲存格各自配對字詞，字詞框要落在它那幾欄的左右邊界內（上下不限，因為列會長高） |
| 13 | 文字配對不是計畫規定的連續未使用字詞序列 | `match_run()`：字詞照頁面繪製順序（`pdftotext -raw -bbox`），每個框的文字要等於一段連續、整字、沒被用過的字詞；段落開頭的項目符號或編號算在這段裡。沒有第二種排序的退路，字詞不拆開 |
| 14 | 0.9 門檻被改成切格 | 改回每個配對字詞 0.9。中文一行常是一個字詞，一行裡只有一個字被遮一半時照這條規則抓不到；`onechar` 反例改成「通過」並寫明是限制 |
| 15 | 覆蓋率先四捨五入才判 | 用未四捨五入的值判，報告才四捨五入 |
| 16 | 對帳器誤報 PATH 和模型名 | `checks/run_check.py`：PATH 分作答和閒置各自比；模型名允許日期後綴 |
| 17 | 天花板清單把缺 S 的題列入 | `cap_judge.py`：每個候選各自列，N1、N2、該 S 三筆都在而且都過才算 |
| 18 | 算繪結果沒留 | `ppt_check.py` 把交付簡報每一頁存成 50 dpi 的 PNG（`render/`），runner 連同成品和結果一起留下 |
| 19 | FEASIBILITY 沒更新 | 正式設定驗完後補（探針、候選離線成品、隔離、磁碟量測） |
| 20 | 可以接受的差異 | 不動 |

第一次檢查之後另外發現並處理的一件事：Claude Code 啟動時列出的 skill 和指令不是只由組別決定（見 `cap_run.py` 裡 `MAX_RESTARTS` 上面的說明）。處理方式：每個 Claude 家目錄一開始放同一份 CLI 狀態檔（`warm` 指令用兩個一行的 session 產生）；啟動清單跟該組凍結的清單不一樣的 session 立刻停掉重來（不花 token、另外計數、最多 10 次）。
