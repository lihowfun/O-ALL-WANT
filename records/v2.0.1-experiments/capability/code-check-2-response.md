# 第 2 次程式碼檢查的處理（2026-11-12）

Codex 判「先改再跑」：第 1 次的 20 點裡 6 點未關閉，另有 8 點新的（21–28）。逐點處理如下。

| # | Codex 指出 | 怎麼改 |
|---|---|---|
| 1 | `guard_paths()` 沒檢查反方向 | 兩個方向都檢查：受保護的資料不能在沙箱看得到的目錄裡，沙箱看得到的目錄也不能在受保護的資料裡（工具副本在使用者家目錄底下是唯一例外，它只露出自己） |
| 3 | 掛載來源可以是絕對路徑、`../` 或往外的連結；校準不核對樣板和工具 | `source_problems()`：來源必須是樣板裡的相對路徑、真實的資料夾，裡面每個連結都不能指到樣板外面，所以樣板的摘要涵蓋掛進去的全部內容。`check_lock()` 改成每個指令都完整核對（計畫、brief、程式、每個樣板、工具副本），校準也是 |
| 4 | 衝突清單漏了工具副本和 CLI 路徑 | 候選的掛載目標不能碰到：共同工具、工具副本的每個路徑、系統目錄、proxy 資料夾、`/tmp`、`/dev`、`/proc`、工作目錄、登入檔、CLI 狀態檔 |
| 8 | 記的不是實際峰值；沒要求量過最大的凍結題 | `Peak`：run 進行中每 10 秒量一次暫存目錄，取最大值，記在 `scratch_bytes`。`cmd_select` 要求每題校準 run 都有量到的峰值，把選上的題裡最大的峰值寫進凍結檔（`peak_of_selected_tasks`）；沒有這個值就不能凍結；開跑前的空間檢查以它為下限 |
| 11 | 表格的改值驗證會被別的物件滿足 | 表格的變體頁只留這張表（其他物件全部拿掉），標記字要是一個完整的字詞，而且落在第一格那幾欄的範圍內 |
| 16 | 對帳器的模型判斷沒沿用 H1 | 逐個 root model 用同一條規則（名稱相同或加日期後綴），有缺模型的訊息就不過 |
| 19 | FEASIBILITY 沒更新 | 已補第 3 節：手造反例、沙箱和隔離、網路探針、候選離線成品、判定和帳本、磁碟 |
| 21 | 校準只綁題目的摘要欄位 | 每次 run 開始前重算題目資料夾的摘要，要等於驗題時的摘要，並寫進紀錄（`task_tree_sha256`）；選題時再核對「現在的題目資料夾 = 驗題報告 = 校準紀錄」 |
| 22 | 可以跳過較早的出題者 | `write_candidates()`：登記過的出題者沒有驗題報告就拒絕（除非他的 session 沒跑成或沒交任何題）。`cmd_select` 重新從每位出題者的紀錄組出候選清單，要跟存檔一致。補題的出題者只有在 `select` 對前面全部出題者算出「合格題不足」之後才能開始 |
| 23 | 有重試時對帳器會崩潰 | 改用字串當 key。`checks/run_check_test.py` 用合成帳本驗：先失敗後成功的 run 對得起來；多一筆計分列、少一筆嘗試、順序不對、token 對不上都被抓到 |
| 24 | 合併儲存格之後的欄界算錯 | 每個實體 `tc` 就是一欄；合併的起點涵蓋 `gridSpan` 欄，被併掉的格子沒有文字、跳過。反例 `merged` |
| 25 | 沒納入版面配置區自己的段落字級 | 實測 LibreOffice 的行為：版面配置的標題區段落寫 60，投影片標題仍照母片算繪成 44（`pdftohtml` 回報 43）。所以推算的 44 是對的，這條繼承不加。反例 `Title 9` 固定這個行為。另外把保險加成雙向：檔案推算和算繪差超過 1.5 點時以算繪為準，不論高低 |
| 26 | 深色底上透明圖表的白字被誤判 | 圖表單獨算繪兩次（白底、黑底）。字詞框裡白底黑底不一樣的地方是透出來的底，兩邊一樣的像素就是字的筆畫；圖表自己有底色的才用「跟中位數差 64」。反例 `dark-chart`（該過，過了） |
| 27 | 圖表內的旋轉文字沒檢查 | 三個來源：圖表 XML 裡任何文字設定帶旋轉或直排；直立的軸（左、右）有標題而沒有明確設成水平；算繪出來的字詞直立或斜放（兩個字以上而高大於寬的 1.5 倍，或四個字以上而高大於寬的 0.9 倍）。反例 `chart-turned`、`chart-axis`。brief 補一句：圖表裡的字也算，直立的軸標題就是旋轉的字 |
| 28 | 評分環境失敗會算成候選失敗 | `ppt_check.grade()`：量測階段出錯時，把交付檔單獨轉檔一次。轉得出來 → `infra`（不是簡報的問題）；轉不出來 → 簡報不合格。空間不夠一律 `infra`。runner 看到 `infra` 就重評一次，還是不行這次 run 就不計分；空間不夠直接停（不算在 3 次失敗裡） |

第 2 次檢查說可以維持的實作細節（固定取前四題、16:9、標題版面配置區、純文字素材、保留 50 dpi PNG、以完整 PDF 字詞當 0.9 的判定單位）都沒動；「中文整行是一個字詞時，單一個字被遮住可能通過」記在 `FEASIBILITY.md` 第 3.1 節的已知限制。
