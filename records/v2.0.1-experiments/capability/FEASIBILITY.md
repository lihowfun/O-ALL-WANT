# 能力型試吃：可行性檢查（不呼叫模型）

照 `PLAN.md` 第 9 節，凍結前要做完。這份會隨實作補完；目前只有 PPT 工具鏈的部分。

## 平台

- Linux server，沒有畫面。系統 Python 3.10，python-pptx 1.0.2。
- LibreOffice 7.3.7.2；Poppler 22.02.0（pdftotext、pdftoppm）；字型 Noto Sans CJK TC。
- 沒有 numpy；原型的像素比對用純 Python。
- 沒有 ffmpeg：影片的部分還不能做（`PLAN.md` 第 10 節的前置條件）。

## 1. PPT 工具鏈（2026-11-10）

程式：`feasibility/make_deck.py`。

- python-pptx 做出帶中文、表格、圖表的簡報，存檔、重開都正常，讀得到圖表類型、數列值和類別。
- 改一個表格儲存格，存檔、重開、LibreOffice 轉 PDF，新的值出現在 PDF 的文字裡。
- pdftotext `-bbox-layout` 給的是字詞框；中文沒有空格，一行常常被當成一個字詞。塞太多字的文字框，字詞框落在框外，看得出溢出。
- **LibreOffice 跟 PowerPoint 的算繪不完全一樣**：python-pptx 做的文字框，LibreOffice 置中顯示，PowerPoint 預設靠左。算繪結果只能當近似，結論要寫明是用 LibreOffice 算繪檢查的。

## 2. 完整看得見的檢查（`PLAN.md` 第 5 節）

程式：`feasibility/ink_proto.py`。每個文字框做四個變體（整張、整張拿掉這個框的文字、只有這個框、只有這個框拿掉文字），畫布四邊各加大 2 吋；「只有這個框」的兩張解除裁切、去掉框的底色和框線、文字改黑色、底改白色。轉 PDF 後用 pdftoppm 以 72 dpi 灰階算成圖，逐像素相減。

| 手造案例 | 墨跡像素 | 覆蓋率 | 框外 | 頁外 | 結果 | 該有的結果 |
|---|---|---|---|---|---|---|
| 正常的標題 | 778 | 1.000 | 0 | 0 | 過 | 過 |
| 塞太多字、超出框的下緣 | 3,090 | 1.000 | 1,383 | 0 | 不過 | 不過 |
| 下半部被色塊蓋住 | 2,379 | 0.624 | 0 | 0 | 不過 | 不過 |
| 白字白底 | 1,101 | 0.000 | 0 | 0 | 不過 | 不過 |
| 框設成裁切又塞太多字 | 2,976 | 1.000 | 1,295 | 0 | 不過 | 不過 |
| 深色底白字（正常設計） | 1,570 | 1.000 | 0 | 0 | 過 | 過 |

- **墨跡只取筆畫中心**：「只有這個框」相減後變暗 128 以上的像素（字覆蓋了一半以上）。第一版用「變化超過 40」連字的邊緣也算進去，深色底白字的邊緣在整張圖裡只差 40，覆蓋率 0.812，誤判成不過；改成筆畫中心後是 1.000。
- **看得見**：整張圖拿掉文字前後，差超過 40。
- **LibreOffice 不理會「裁切」設定**（`vertOverflow="clip"`），超出的字照樣畫出來，所以這一例是被「框外」抓到，不是被覆蓋率抓到。
- 門檻（筆畫中心 128、看得見 40、覆蓋率 0.95、框外容許 2 點、畫布加大 2 吋）還沒凍結，要在出題後、校準前用全部反例再驗一次。

**還沒做**：每個字詞各自的覆蓋率（要先完成字詞配對）、旋轉、群組、表格和圖表裡的文字、繼承來的字級、透明背景、改值後重新算繪的圖形比對、`PLAN.md` 第 12 節的其他項目。
