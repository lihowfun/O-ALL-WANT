## 結論

- **合併：可選用**。兩格都是「可選用」（品質未定、成本不算太貴）。配方維持現狀：只能用 `--skills oaw-bugbash` 明確選裝，不進預設。
- **BASH 驗收兩格都沒過**。
  - 最直接的原因：兩條「嚴重」缺陷中的 remove-bundled-skill，兩格、四組、四家評分都沒有人抓到（校準時兩格的 N 各跑 3 次，也都沒抓到）。BASH 要求嚴重缺陷零漏失，所以這次沒有任何一組過得了。
  - 另外偵測也沒有兩家都判「更好」。
- **Claude 格**：F 抓到 5/6，N 3/6，兩家評分一致。只多 2 條，區間碰到 0，偵測「未定」。沒根據的回報每份少 1.08 個，兩家都判「更好」。成本 0.93 倍，在範圍內。
- **Codex 格**：F 抓到 2/6，N 0/6，偵測「未定」。沒根據的回報兩家都判「等價」。成本 1.39 倍，95% 區間 [1.12, 1.72] 跨過 1.5，判「未定」。
- **一句提示（C）**：
  - Codex 格的 C 抓到 4/6，比 F 多。C 對 N 的偵測兩家都判「更好」，但 C 也漏了嚴重缺陷，照 BASH 規則，品質從「更好」降成「未定」。

- **主場**：只測指令列，沒測瀏覽器。結果不是「排掉」，所以不觸發「瀏覽器是不是主場」的提問。

## 看紀錄得到的觀察（事後才看的，不是登記過的檢定）

1. **Claude 格的 F 回報得比較少、比較準。** F 每份只回報 2.67 個缺陷（N 3.83、C 5.92），抓到的條數和 C 一樣是 5/6，沒根據的回報最少。
2. **Codex 格的 F 回報得更少。** Codex 原生本來就很少回報（每份 0.67 個，6 條缺陷一條都沒抓到）。F 每份 0.58 個，比只加一句提示的 C（2.08 個）少，抓到的條數也比 C 少（2/6 對 4/6）。
3. **remove-bundled-skill 這條沒有人抓到。** 觸發方式要先把 skill 資料夾設成唯讀、讓 `remove --apply` 失敗回滾，再跑一次同一個指令，才看得到 `.oaw/install.lock` 沒有清掉。BASH 的「嚴重零漏失」因此在這次設計裡沒有一組過得了。
