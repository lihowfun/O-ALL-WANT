## 1. 判定程式的輸入摘要（2026-11-09，校準後）

- **問題**：`i16_judge.py` 原本用檔名當 `inputs` 的 key。兩格的作答檔都叫 `rows.jsonl`，Claude 格那份被蓋掉；重播檔也沒有記。

- **影響**：只影響紀錄。重算後下限和天花板與原本完全相同。評分、重播、作答程式都沒動，正對照的版本綁定仍然有效。

## 2. 黑箱計數的稽核（2026-11-09，Codex 格主分析後）

- **問題**：`i16_run.py` 把 Codex 的每個工具呼叫當成一整個字串來掃。
  - Codex 的指令是 JavaScript 字串，換行在字串裡是「反斜線加 n」兩個字元，不是真的換行。
  - 例如寫輔助腳本的 heredoc：第一行是 `cat > bugbash_out/run.py <<'PY'`，後面幾行在呼叫 `oaw/scripts/oaw.py`。掃描器把整段當成同一行，看到開頭的 `cat` 和後面 `scripts/` 底下的檔案，就算成一次讀原始碼。
  - 一行裡有好幾個指令時也會這樣，例如 `cat project/AGENTS.md` 換行後接 `python3 project/scripts/context_hub.py --help`。
- **處理**：
  - 原本的計數照樣保留，因為 `i16_run.py` 的 sha256 綁在正對照和每一列上，不能改。
  - 另寫 `i16_source_audit.py`，從原始作答紀錄逐行重算一次，只用在黑箱的描述分析。規則寫在檔頭：Codex 的字串先還原再切行，每行再切成單一指令，只有讀取類動詞在指令開頭才算，`cat > 檔案` 不算。
- **結果**（校準 36 次，加上 Codex 格主分析 48 次）：

| 格 | 組 | 原本的計數 | 稽核後 |
|---|---|---|---|
| Codex | N | 4 次，在 4 列 | 0 |
| Codex | C | 7 次，在 5 列 | 0 |
| Codex | D | 14 次，在 8 列 | 0 |
| Codex | F | 12 次，在 7 列 | 0 |
| Claude | N（校準） | 1 次 | 1 次 |

  - Codex 的 37 次全部是上述誤判。另外抽查 Codex 所有字串裡同時有讀取類動詞和 `scripts/` 路徑的行，沒有漏算真的讀取。
  - Claude 那 1 次是 `cat p3/.agents/skills/scripty/scripts/run.py`：測試者自己建的 skill 範例檔，不是 OAW 原始碼。PREREG 寫明「範例檔放在 scripts/ 底下也照算」，所以照算。
- **影響**：黑箱只做描述，不進判定。PREREG 要求的「排除有讀碼的列」描述分析，RESULT 會同時用原本的計數和稽核後的計數各做一次。
