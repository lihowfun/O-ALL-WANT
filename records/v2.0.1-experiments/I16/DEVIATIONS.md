## 1. 判定程式的輸入摘要（2026-11-09，校準後）

## 2. 黑箱計數的稽核（2026-11-09，Codex 格主分析後）

- **問題**：`i16_run.py` 把 Codex 的每個工具呼叫當成一整個字串來掃。
  - Codex 的指令是 JavaScript 字串，換行在字串裡是「反斜線加 n」兩個字元，不是真的換行。
  - 例如寫輔助腳本的 heredoc：第一行是 `cat > bugbash_out/run.py <<'PY'`，後面幾行在呼叫 `oaw/scripts/oaw.py`。掃描器把整段當成同一行，看到開頭的 `cat` 和後面 `scripts/` 底下的檔案，就算成一次讀原始碼。
  - 一行裡有好幾個指令時也會這樣，例如 `cat project/AGENTS.md` 換行後接 `python3 project/scripts/context_hub.py --help`。
- **處理**：
  - 原本的計數照樣保留，因為 `i16_run.py` 的 sha256 綁在正對照和每一列上，不能改。
  - 另寫 `i16_source_audit.py`，從原始作答紀錄逐行重算一次，只用在黑箱的描述分析。規則寫在檔頭：Codex 的字串先還原再切行，每行再切成單一指令，只有讀取類動詞在指令開頭才算，`cat > 檔案` 不算。
