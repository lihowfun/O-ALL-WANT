## review_out/decision.md

RECOMMENDATION: change

Replace the unconditional session-start rebuild with `ensure`, and compare
`catalog_sha256`, `aliases_sha256`, and `format_version` before reuse. The
proposed.patch changes only docs/index-directions.json. Keep the existing
missing/unreadable/mismatched-index rebuilds, checks before lookup and after
input writes, release rebuild, and verification reporting. Active guidance has
not been edited.

The recurring build is required by loaded agent guidance, rather than an
application freshness mechanism. AGENTS.md delegates to docs/agent-guide.md,
which explicitly designates docs/index-directions.json as operational guidance.
Its `session_start: rebuild` explains the recorded startup actions.
docs/fields.md already defines `ensure` and all three proposed comparison fields;
there is no need for another workflow, skill, or application change. catalogue.py
offers only build and lookup commands: an agent must perform the comparison;
there is no `catalogue.py ensure` command. Removing the startup direction
entirely has undefined semantics in the documented format, whereas replacing
its action uses the existing contract.

Saved evidence supports a narrower freshness requirement than rebuilding every
session. The table distinguishes recorded behavior from the candidate's
deterministic simulation using the same saved inputs and actual application
functions. Build counts include the separate release action.

Each row is traceable to runs/<session>/state.json, events.jsonl, request.txt,
and manifest.json. The capture probes are recorder actions in isolated copies,
not evidence that an assistant followed revised guidance. c310 is an observed
correctness failure under the current directions: a startup build cannot
protect against a later alias edit.

Changing only `session_start` would be unsafe. The current reuse key covers
only catalogue bytes. It would miss the changed aliases in c305 and c310 and
the incompatible format in c306. catalogue.build consumes both JSON inputs;
catalogue.lookup rejects incompatible formats. Thus both input digests and
the reader's expected format belong in the key. Use their metadata values,
not timestamps or a remembered assertion that files are unchanged. Missing
selected metadata is unreadable under docs/fields.md and still requires a
rebuild. Keep the checks after writes and before lookups so later changes
invalidate reuse.

Do not add producer to ordinary reuse checks. README.md, catalogue.py,
tests/test_catalogue.py, and c303 agree that producer releases 1.7 and 1.8
produce compatible format-2 indexes; the reader does not require producer
identity. Adding it would rebuild c303 without improving lookup correctness.
This does not relax distribution: docs/release.md and c309's bundle audit
require a build during that session and its producer stamp. The patch retains
`release: rebuild`, even when all reuse fields match. It also retains
`completion: report_verification`; final replies should report the freshness
comparison or rebuild and the verification performed.

The falsifiable hypothesis is that these directions eliminate builds for valid
unchanged ordinary lookups, preserve rebuilding for stale/missing/unreadable
indexes and releases, and fix alias edits without degrading delivered results.
review_out/replay.py simulates baseline, candidate, startup-only, and
producer-inclusive policies against all ten states. It derives the candidate
from the delivered patch, reproduces the recorded baseline lookup values and
build counts, and checks candidate results against fresh application builds.
replay-results.json records 11 baseline builds versus 7 candidate builds and
10/10 correct candidate lookups, versus 9/10 baseline. These are mechanism
checks, not measured assistant performance. A matching format and selected
metadata assume a normally produced index; they do not prove protection from
arbitrary payload tampering.

The evidence does not establish token, cost, or latency savings. runs/README.md
says build cost was not collected and there are no revised-guidance sessions.
The manifest records model local-assistant-4 and high effort, but lacks a full
host/version/environment/permission snapshot for matched agent trials. Hash
checks also find that every captured AGENTS.md hash differs from today's file,
despite the capture README's general unchanged-files statement. All other
loaded-path hashes, catalogue.py hashes, and request/state/event/final artifact
hashes match. The operational cause is independently visible in current
guidance, but these captures are not a fully matched current-policy experiment.

For validation before adoption, evaluation.json fixes all ten tasks, three
repetitions per task, correctness/release/reporting/permission assertions, and
complete resource accounting including loading guidance and checking freshness.
Run baseline and candidate in isolated copies with the same model, effort,
host/version, environment, repository state, and permissions. Retain outputs,
checks, actual build actions, and measured tokens/time/cost; verify unchanged
lookup reuse and all invalidation cases. Use scripts/improvement.py compare
only after those genuine artifacts exist. No agent comparison or acceptance
has been fabricated. The proposal record is
review_out/.oaw/improvements/ef29e4dc13c9.json, with status proposed.
