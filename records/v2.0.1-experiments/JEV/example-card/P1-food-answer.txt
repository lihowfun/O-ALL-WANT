### What the saved sessions establish

`docs/agent-guide.md` delegates operational behavior to this JSON document;
`docs/fields.md` defines its actions. `catalogue.py` never loads the directions
and has no automatic freshness operation. This is an assistant guidance change;
the assistant must perform the comparisons before choosing whether to build.
Changing application code or the host's separate code index would not remove
this explicit startup requirement.

### Why this particular edit

Deletion alone would remove a defined operational setting without specifying a
safe startup action. Replacement with the existing `ensure` action is sufficient.
It reuses only after all selected metadata matches the current inputs and reader.
The extra two field names are the only added guidance context.

Changing startup alone is unsafe: under the documented field-selection rules,
it would reuse c305's outdated alias data and c306's incompatible format. Adding
the alias hash alone still misses c306. `catalogue.signature`, `build`, and
`lookup` establish that both input hashes and format are the relevant key.
Missing selected metadata is unreadable and must use the existing rebuild fallback.

Exclude `producer` from ordinary freshness checks. `README.md`,
`CatalogueTests.test_producer`, and `catalogue.lookup` confirm that producers 1.7
and 1.8 emit compatible format 2 and that the reader does not test the stamp.
Keep `release: rebuild`: `docs/release.md` requires a build from the distribution
session and its producer stamp even if lookup data is identical. A producer match
alone would not prove that audit condition.

Keep the current missing/unreadable/mismatched rebuild fallbacks,
`before_lookup: ensure`, `after_input_write: ensure`, and verification reporting.
The expanded key applies at every existing ensure trigger, including changes
between startup and lookup. No additional release guidance belongs on ordinary
lookup paths.

### Validation and its limits

[replay.py](replay.py) interprets the documented guidance over the saved event
schedule using the existing `catalogue` functions. [evidence.json](evidence.json)
retains each baseline, candidate, and rejected-alternative action and lookup.
It reproduces every recorded baseline action/result, including c310's failure.

| Mechanical replay | Lookup cases correct | Build calls | Bundle audit |
| --- | --- | --- | --- |
| Baseline | 9/10 | 11 | Pass |
| Proposed settings | 10/10 | 7 | Pass |

The proposal skips five startup builds (c301, c302, c303, c309, c310), retains
the five recovery builds (c304–c308), retains c309's release build, and adds
c310's necessary post-write build. The net reduction is four calls. Three of
the eight ordinary lookup sessions can reuse their initial index; the remaining
five require recovery. Five additional synthetic checks verify recovery when
each selected metadata field is missing and after a catalogue edit at both
the post-write and before-lookup triggers.

These are deterministic semantic checks, not observed candidate assistant
behavior. Both changed components lack a matched agent comparison: their
behavioral effect is **confounded/unmeasured**. The replay supports the startup
replacement's predicted skipped builds and the expanded key's necessity, but
does not establish model compliance or net token, time, or monetary savings.
No elapsed build cost was captured; capture timestamps are not build timings.
Do not interpret four fewer calls as a measured runtime reduction.

All saved request/state/event/final hashes and application hashes verify.
The loaded operational guide and delegation document hashes match current files,
as does c309's release document. However, all ten manifests record a different
`AGENTS.md` hash from the current workspace. The captured historical bytes are
not available here, so the capture's blanket unchanged-file claim cannot be
fully verified. The report retains this discrepancy rather than treating the
sessions as fully matched to today's host guidance.

The original model is recorded as `local-assistant-4` at high effort; matching
host/version, permissions, resource measurements, and revised-guidance sessions
are absent. [evaluation.json](evaluation.json) fixes a future three-repeat,
ten-case paired evaluation contract. Establish a common repository/guidance
snapshot, hold model, effort, host/version, environment, permissions and grader
constant, retain both arms' complete traces and failures, and measure resources.
`improvement.py compare` was not run: there are no genuine matched assistant
trajectories, and replay output must not be mislabeled as such.
