# JEV：小模型的是／否判定，第一次校準

2026-11-14。依 [D50](../../digestion-2026-11-03/ingest/DECISIONS.md)。「JEV」是 2026-11-08 Figma PM OS 那次吸收時提到的做法
（[紀錄](../../intake-2026-11-08-figma-pmos/MERGE.md)）：用一個小模型回答窄的是／否問題，並附可核對的原文引句。
當時只做了離線校準工具（`scripts/judge_calibration.py`），沒有任何判定模型被准入。這一頁是第一次量小模型本身。

## 結論

**照開跑前寫的條件（[RULE.json](RULE.json)），正式結果是「未准入」：RULE.json 的四個數字條件裡，準確度的三項兩次都過，「token 不超過全價評分者的一半」兩次都沒過；計分程式另外檢查的「沒有呼叫錯誤」兩次都過。**
要不要仍然把它放進快篩，由 owner 決定；lead 沒有改條件。

## 量法（以下數字都是這一種）

- 判定模型：Claude Code 2.1.322／`claude-haiku-5-5`／effort low，不給任何工具，每份報告一個全新 context 的請求，訂閱計費。
- 題目：EGM 原生校準第二批的四份審查報告（[結果紀錄](../EGM-calibration/RESULT.md)），每份問同樣的 30 個已知缺陷
  「報告有沒有抓到」，標成 `detected`、`mention-only` 或 `absent`。`detected` 和 `mention-only` 要附報告原文的引句；
  程式逐字核對（連續空白視為一個），對不上的算 `unknown`。提示給每個缺陷的敘述與判準，不給 key 裡另外列的佐證清單；敘述與判準本身若帶有檔案路徑，照樣在提示裡。
  八次呼叫的提示與原始回覆（含引句）都在 [prompts/](prompts/) 與 [replies/](replies/)，可以重查引句。
- 標準答案（[gold-egmcal.json](gold-egmcal.json)）：兩位全價評分者（`gpt-6-astra`、`claude-fable-5-2`）在登記的歧見核對之後標籤相同的 114 格
  （阻擋級 36 格、次要 78 格）；兩位仍不一致的 6 格（都是次要項目）不計。114 格裡 `detected` 25、`mention-only` 16、`absent` 73。
- 快篩只用二分的答案（`detected` 對其他），所以准入條件看二分；三分類的數字列出來供對照。
- 同一份提示跑兩次（各自全新 context）。token 是 logical 總量（含快取讀取）。

## 限制

- 只有一份被審文件、30 個缺陷、四份報告。這不是對其他題型的結論。
- 標準答案是兩位評分者的一致標籤，不是另外核實的真相；其中一位和 JEV 同一個家族。
- 這裡量的是「對照一份已知清單，報告有沒有抓到」；沒有量「找出清單以外的缺陷」，也沒有量任何放行類的判斷（同意、授權、安全、隔離）。
- 每份報告一次請求、一次問 30 項。一項一問的做法沒有量。
- 2026-11-08 那次篩選為這類判定訂過更嚴的門檻（另外核實的資料上三分類 macro-F1 ≥ 0.98）。這次的三分類 macro-F1 是 0.864 與 0.871，沒有達到；
  這次的准入條件只看快篩會用到的二分答案，條件是 lead 在開跑前自己訂的。

## 獨立重算

這份紀錄的第一版交給一個全新 context 的 Codex（lead 啟動時指定 `gpt-6.1-sol`）重算，結果在 [RECOUNT.json](RECOUNT.json)。
它自己從原始評分檔重建 114 格標準答案、自己計分：表裡的數字全部重現（24 項裡 22 項相符，另外 2 項是「附的檔案裡查不到佐證」）。它判 **FAIL**，都不是數字錯：

| 問題 | 嚴重度 | 這一版怎麼改 |
|---|---|---|
| 沒有附原始回覆，引句核對無法重查 | 中 | 補上九次呼叫的提示與原始回覆 |
| 「條件在開跑前寫定、之後沒改」超出檔案能證明的範圍 | 中 | 改寫成 lead 的陳述 |
| 「五個條件」裡的「沒有呼叫錯誤」不在 RULE.json，是計分程式加的 | 中 | 分開寫：RULE.json 四項，程式另一項 |
| 試跑的 3,464 token 沒有紀錄、比較的範圍沒寫清楚、佐證路徑的說法太寬、標題的「又快又便宜」沒有被證實 | 低 | 補紀錄、寫明範圍、改寫說法、標題改成中性 |

這些修改之後沒有再送一次確認。
