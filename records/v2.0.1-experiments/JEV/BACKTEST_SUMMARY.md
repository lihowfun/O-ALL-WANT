# 快速判定規則第 0 版：用過去的紀錄回測

2026-11-14。規則是 [FAST_SCREEN_RULE.md](FAST_SCREEN_RULE.md)（SHA-256 開頭 `f6c02650292d8de6`，回測之前寫定）。
回測由一個全新 context 的 Codex（`gpt-6.1-sol`）只讀 `records` 分支與發佈線的檔案做成，逐筆附檔案與行號：
[backtest/BACKTEST.md](backtest/BACKTEST.md)、[backtest/BACKTEST.json](backtest/BACKTEST.json)。
lead 抽查了 X2、U2 兩筆的數字與 H1 的 token 倍數，和原紀錄相同；其餘各筆沒有逐一核對。

## 這是什麼、不是什麼

- 過去的實驗不是照這條規則設計的。回測只是把每一筆「當時記下來的數字」套進規則，看規則會給什麼答案。
- 沒有重跑任何作答，沒有重新評分，也沒有用判定模型。紀錄裡缺規則需要的數字時，那一筆就是「不能回測」，不估。
- 同一樣食物在不同次試吃各算一筆（例如程式碼地圖有五筆、EGM 有三筆），所以筆數不是食物的種類數。
- 規則的「YES」只代表「吸收成可選用」。

## 結果

共 37 筆紀錄，其中 24 筆可以回測，13 筆不能（不是食物對原生的比較，或缺數字）。

| 規則的答案 | 筆數 |
|---|---:|
| NO，停在 B（原生已經做到九成以上，食物那一組不用跑） | 14 |
| NO，停在 C（食物沒有補上、弄壞了東西，或 token 超過 1.5 倍） | 7 |
| YES | 3 |

和當時實際的處置比：

| | 筆數 | 是哪些 |
|---|---:|---|
| 相同 | 10 | 9 筆規則 NO、當時也沒有吸收（codegraph、graphify、court-skill、只有 skill 的審查做法）；1 筆規則 YES、當時是可選用（I16 bug-bash 配方） |
| 規則 NO，當時留作「可選用」 | 9 | 程式碼地圖 4 筆（X1 與三次確認）、EGM 3 筆（X2、自測、V5）、TokenEconomizer 2 筆 |
| 規則 NO，當時留作「預設」 | 1 | H1（整包 OAW）：Claude 那一格原生已達 0.92，停在 B；Codex 那一格原生 0.79，但總 token 是 1.92 倍，停在 C |
| 規則 YES（可選用），當時的處置不同 | 2 | 審查政策的兩版（X3 的 A 組當版沒過自己的門檻、修正後的 X3b 進了預設） |
| 當時沒有處置 | 2 | FIXCHECK（五個修正合在一起）、U2 對照卡：規則都是 NO，停在 B |

- 沒有任何一筆是「規則說 YES，而當時把它排掉」。
- 規則說 NO 而當時留下來的 10 筆，各自當時的判定與處置在 [backtest/BACKTEST.md](backtest/BACKTEST.md) 逐列列出；H1 留作預設是產品決定（D45）。
- 這些實驗記下來的花費（logical token，兩家不相加）：H1 Claude 24,056,558、Codex 23,883,264；X1 Claude 24,933,421；
  X2 Claude 47,237,230；X3 Claude 3,603,037；X3b Claude 3,016,664；FIXCHECK Claude 8,154,700；U2 Codex 5,119,897。
  紀錄裡沒有「如果照快速判定做會花多少」的數字，所以這裡不算省了多少。

## 限制

- 回測用的是各實驗自己的品質量尺（偵測數、覆蓋率、通過的情境數），和規則設計的「3 題主場題的檢查清單」不是同一種東西。
- 多個 host 的實驗，只要有一個 host 停在 B 且沒有共同的 YES，這一筆就記成 NO 停在 B；這是回測者的記法，規則本身沒有寫。
- H1 的 token 倍數有兩種記法：總量 2.58／1.92 倍，逐題幾何平均 1.45／1.48 倍。回測用的是總量。
- 規則第 0 版還沒有用在任何一樣新的食物上。
