# D40：2.0.1 的預設要不要再減（交給 owner 開 Fable 5.2 決定）

> 2026-11-11。H1 的結果（`RESULT.md`）落在 D40 事先點名「agent 不選邊」的情況，所以這份只整理事實和選項，不做推薦。

## 為什麼 agent 不決定

D40 和 `docs/plans/v2.0.1-value-check.md` 第 6 節（`claude/oaw-2`）先講好的用法：

- 任何一格「更慘」或「雞肋」→ 提案把對應零件移出預設。
- 「有幫助」→ 照實寫進 README，不擴大解釋。
- 「沒差」→ 預設維持現狀。
- **兩格方向相反、退步追不到單一零件、或某格沒有結論** → 交給 owner 開 Fable 5.2。

H1 的結果同時碰到兩個點名的情況：

1. **Claude 格沒有結論**（詞是「未定」）。
2. **B 類（記憶）兩格方向相反**：Claude 格 0 贏 2 輸、Codex 格 2 贏 0 輸；superseded-2-b1 這一題兩格正好相反。

## 事實（細節和區間見 `RESULT.md`）

- **L 對照**（只有 Codex 格）：兩行規則對 N 更好（+0.30）；O 對 L 未定（−0.14）。B 類記憶 L 4/4、O 2/4、N 0/4。

## 事後看到的機制（描述，不是登記過的檢定）

- **記憶，Claude 格**：O 輸的兩題，原生 N 都是去 grep 前面 session 的 transcript 找回事實；O 改查 OAW 的專案筆記和 auto-memory，兩邊都是空的，就沒有再翻 transcript。
- **記憶，兩格**：O 只有在對話明講要記時才寫筆記（4 題中 1 題）。OAW 的 `AGENTS.md` 是「被要求時、或決定日後難以重建時才存」；L 的規則沒有條件，4 題都寫了。
- **token**：C 類多出來的幾乎都是「大改動找一個全新 context 審查」的 subagent。Codex 格的 L 也有這條，C 類花的跟 O 差不多。分數上只換到 Codex 格 design-1-c1 一題。

## 可以選的方向（不排序，不是 agent 的推薦）

| 方向 | 依據 | 代價或風險 |
|---|---|---|
| A. 預設不動，README 照實寫兩格結果和 token | 合併是「未定」，不是「更慘」或「雞肋」；Codex 格「有幫助」 | Claude 格記憶退步留著；token 多 2–2.6 倍照寫 |
| B. 把「大改動找全新 context 審查」移出預設、改成選用 | C 類 token 主因，分數幾乎沒換到 | Codex 格唯一的 C 類贏題可能跟著消失；要先確認跟 X2／D37 定的 auto 審查方式怎麼銜接 |
| C. 改記憶規則再發佈（例如改成沒有條件的「記下來、開工先讀」，或 recall 找不到時提醒回頭翻原生紀錄） | Claude 格退步追得到這個機制；L 的規則在 Codex 格 4/4 | 這是改內容，不是移除；改完沒有量過，要不要先重測由 owner 決定（要預算） |
| D. 延後發佈，加題重測 | 整體最小可偵測差 0.16–0.17，每類只有 4 題 | 要新的預算和時間 |

這幾個方向可以組合（例如 A 加 C）。
