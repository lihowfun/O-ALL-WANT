## 差在哪（描述，不改判定）

以下是看紀錄得到的觀察，事後才看的，不是登記過的檢定。

1. **筆記寫不寫是 B 類的關鍵。** L 的兩行規則是「後面會用到的決定和事實寫進 NOTES.md，開工先讀」，4 題都寫了、都記得。O 只有在 explicit-1-b1（對話裡明講要記）時寫了筆記（Claude 寫 `.agents/memory.md`、Codex 寫 `docs/decisions/`），另外 3 題兩格都沒寫。OAW 的 `AGENTS.md` 寫的是「被要求時、或決定日後難以重建時才存」，是有條件的。
2. **Claude 格 O 輸，是因為找記憶的地方換了。** Claude 原生有兩條管道：explicit-1-b1 的 N 用了 Claude Code 自己的 auto-memory（`MEMORY.md`）；Claude 格 O 輸的兩題（passing-1-b1、superseded-2-b1），記得的 N 都是在最後一個 session 直接 grep 家目錄裡前面 session 的 transcript（`~/.claude/projects/*.jsonl`），把事實找回來。同兩題的 O 改用 `oaw-evidence` skill、`context_hub.py memory recall`／`search` 查 OAW 的專案筆記，也看了 auto-memory 資料夾；兩邊都是空的（前面的 session 沒寫），就沒有再去翻原生 transcript。Codex 格剛好相反：N 沒寫記憶檔、也沒回頭翻紀錄，4 題兩次都沒記得；O 贏的兩題，explicit-1-b1 靠自己寫的筆記，superseded-2-b1 是 OAW 的 recall 查不到之後，接著 grep `~/.codex/sessions` 裡前面的 transcript 找回來。
3. **C 類多花的 token 主要來自「大改動找一個全新 context 審查」。** O 在 C 類每題都開了 subagent（Claude 1–4 個、Codex 1–3 個）。L 也有同一條規則，C 類總量 6.04M，跟 O 的 5.51M 差不多，都是 N 的 3 倍左右。Claude 格 design-3-c1 的 O 花了 6.28M、36 分鐘，是全部最貴的一筆。
4. **審查沒有換到分數。** C 類幾乎全部天花板，O 唯一贏的一題是 Codex 格 design-1-c1（O 10/10，N 平均 9.5）。
