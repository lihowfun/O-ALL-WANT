## 限制

- 一份文件、每格兩次。這不是母體推論，也不是兩個 host 誰比較強的比較。
- key 是兩份歷史審查的聯集，量的是「對那些發現的涵蓋」，量不出精確度；key 以外的真缺陷不在計分內。
- 9 項阻擋級裡有 3 項（K14、K15、K18）集中在同一塊程式。
- 兩格都有歷史上的家族重疊：這份計畫由 Claude 起草，歷史上被 Opus（EGM）和 sol（原生）各審過一次。全新 session 不能證明訓練或家族記憶不存在。
- 評分者之一（astra）同時是 key 的整理者；它對 key 很熟，但評分時不知道報告的來源。
- 控制與稽核用的 session（lead）沒有逐筆計量，所以上表不是整個研究的總成本。

## 需要 owner 決定的事

照預先登記，只有「有空間」才會問要不要出資跑 EGM；「無結論」是停下來、不補抽、不換文件。這一階段的形式判定是無結論，
所以照字面是到此為止，EGM 維持使用者明確選用，沒有新的判定。

如果 owner 接受上面第 2、3 項的事後變更，把「照標籤算是有空間」當成這一階段的結果，下一步才是出資的問題。EGM 那一段的規模：

- 設計保留的額度是歷史單價的 1.3 倍：18,480,203 × 1.3 ≈ 24.0M Claude logical token，另加合併步驟與評分約 0.5M。
- 這個實驗 Claude 已花 7,207,968。加上保留額是約 31.7M，**超過 30M 的實驗上限**，要跑的話上限要提高；若實際用量接近歷史單價，合計約 26M。
- 能回答的：在這一份文件上，EGM 的交付是否比兩次原生審查合併後多找到已核實的阻擋級缺陷，而且沒有漏掉原生找到的、沒有新增嚴重的不實指控。
  不能回答的：其他文件、自動啟用是否划算。

**owner 的決定（2026-11-14，[D49](../../digestion-2026-11-03/ingest/DECISIONS.md)）：不繼續。** 這一階段以形式判定「無結論」結案，不跑 EGM 那一段；EGM 維持使用者明確選用。這不是對 EGM 的判定。
