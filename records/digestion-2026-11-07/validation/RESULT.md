# 驗證實驗結果（2026-11-07）

依 `PREREG.md`（f1fb9bb，任何新作答之前推上）。每個實驗的程式和判定規則都在開跑前 commit。Linux，Claude Code 2.1.287，訂閱計費；第二位評分者是 Codex CLI 0.167.0（`gpt-6.1-sol`，reasoning high）。

## 結論
**不是單純的自嗨，但也沒有證明 OAW 比較好。** 用更嚴的方法重看，結果有三種：
- **別人的東西確實有優點**：
  - codegraph 在它自己的主場，token 是原生的 0.73 倍，工具呼叫只有 0.23 倍。
  - EGM（V2 內附的元件）多抓缺陷這件事，在 3 個 seed、兩家評分者下都站得住。
- **這些優點有代價，而且是量得到的**：
  - codegraph 在主場的答案比原生錯得多，兩家評分者都這樣判。
  - EGM 要原生 28 倍的 token。
- **我們自己的東西也有同樣的弱點**：OAW 的 code map 在 Haiku 上，三次評分裡有兩次判「錯誤陳述比原生多」。和 graphify 一樣，弱模型拿到地圖會講錯。

量測本身：
- **覆蓋率的解析度不差**：題目固定時，能偵測的最小差距約 2–9 個百分點。研究報告外推的 27–60 是二元的對錯題，不適用我們逐條事實給分的覆蓋率。
- **錯誤陳述數和評分者最不可靠**：
  - 同一批答案換成不同家族的評分者，事實標籤的一致度只有中等，kappa 0.46–0.62。
  - Codex 數出的錯誤陳述是 Opus 的 2–19 倍。
  - 以前的「評兩次」是同一個 Opus 評兩次，一致度 0.97，幾乎不是獨立的第二意見。

## 各實驗
### V1 解析度與四類重判（不花 token）
- **重判 20 個（食物 × 條件）**：等效 8、未定 8、更差 2、更好 2。區間用題內 bootstrap、題目固定。
- **覆蓋率**：ERPNext 4 題 × 3 次，能偵測的最小差距 0.02–0.09。把題目也當隨機抽樣的話，約 0.10。
- **錯誤陳述**：每份答案能偵測的最小差距 0.27–0.55 個，太吵。
- **token**：題目固定時，區間不寬；把題目當隨機時是 0.4–2.8 倍，幾乎不能判。
  - codegraph 在 Opus 4.8 的 token 比，用逐題對數平均算是 1.50 倍，區間 1.33–1.66，跨過 1.5 的門檻。
  - 帳本用中位數比算出 1.72。成本這一關本身也在雜訊裡。
- **樣本規劃**：同樣的作答次數，題目多比重複多划算。
  - 4 題 × 3 次，把題目當隨機時能偵測約 0.10。
  - 12 題 × 1 次是 0.089，8 題 × 1 次（題目固定）是 0.10。
  - 要到 0.05，需要約 40 題。
- **規則本身的漏洞**：同一格的幾次分數完全相同時，bootstrap 區間會縮成一點，「更好／更差」會被誤判。
  - EGM 第一輪的「更好」區間是 [0.67, 0.67]。
  - V6 F 組的「更好」只來自 c4 的一條事實、2 次。

### V8 codegraph 的主戰場
- **設定**：VS Code @29ad5e7（20,942 個檔案）。題目來自 codegraph 自己的 README 和 benchmark。模型用它 benchmark 的 Opus 4.8 high，每組 4 題 × 3 次。
- **索引成本**：8 分 54 秒、2.2 GB、峰值記憶體 12.7 GB。ERPNext 是 15 秒、189 MB。
- **效率**：
  - token 中位數比 0.73，逐題區間 0.64–0.97。
  - 工具呼叫 0.23 倍。
  - 時間 1.07–1.25 倍。
  - codegraph 的工具在 12 次裡被叫用 23 次。這次 agent 真的有用它，ERPNext 那次沒有。
- **品質**：兩家都判變差。
  - 錯誤陳述：Opus 15 對 7，區間不含 0；Codex 24 對 12，區間不含 0。
  - 覆蓋率：Codex −0.11，區間不含 0；Opus −0.05，未定。
  - 錯誤集中在 q1、q2。
- **D29**：品質變差 → 排掉。
- **不能並排比**：README 說省 62%，它量的是效率、不評品質；我們這次量的是品質加效率。

## 建議改的試吃規則（需要 owner 點頭才改 D29，下面是建議）
1. **第二次評分一定換不同家族（Codex）。** Opus 評兩次幾乎是同一個意見（kappa 0.97），跨家族才是獨立的第二意見。
2. **錯誤陳述數只在兩家都成立時才算數**，單一家族只當參考（V3、V4）。
3. **題目多、重複少，換掉天花板題。** 預設 12 題 × 1 次，不用 4 題 × 3 次。
4. **零變異保護。** 同一格分數全部相同時，用整份試吃的合併題內變異當區間下限，不讓區間縮成一點。
5. **排掉之前，至少要有一個「食物自己的主場」條件**（V8 改變了 codegraph 被排掉的理由）。
6. **成本門檻看區間。** 只有區間下界超過 1.5 倍才算「確定太貴」，否則記「成本未定」。
