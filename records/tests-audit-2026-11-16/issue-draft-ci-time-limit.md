標題：CI：Windows＋Python 3.10 的測試步驟貼近 900 秒上限，main 上已逾時一次
標籤：enhancement

## 現象

- run 43615890860（`95dd28a`，push 到 `main`）：windows-latest＋Python 3.10 的 behavior-regressions 逾時（上限 900 秒），整次 CI 紅燈。同一份內容在 PR 的 CI 是綠的（run 43614976092）。
- 這一格測試步驟的時間（CI log 的 `Ran N tests in X s`，688–721 個測試時）：559、740、784、851、882 秒。
- 最近三次整格 job 的時間（788–797 個測試）：634、758、816 秒。同三次的其他格：Ubuntu 102–145 秒、macOS 179–263 秒、Windows＋Python 3.13 408–576 秒。

## 影響

- 一個 PR 的 CI 要等最慢的這一格，大約 11–14 分鐘。
- 風險（不是量到的結果）：這一格離上限很近，測試再增加可能更常逾時。逾時的紅燈本身分不出是程式的問題還是單純跑得慢：那次沒有測試彙整，看不出慢在哪裡。
- 那次紅燈發生在合併之後的 `main`；lead 當時沒有看那次結果。

## 要做（下一版決定用哪一個）

- 量 Windows＋Python 3.10 上每個測試模組的時間，找出最慢的幾個。
- 上限不要跟著測試數量一起被吃掉：依平台設定上限，或把慢的測試分組跑。
- push 到 `main` 的 CI 結果要固定有人看。
