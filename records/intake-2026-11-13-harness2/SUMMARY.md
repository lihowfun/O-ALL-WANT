# Harness²：我們吸收了什麼、參照了什麼、沒有拿什麼（2026-11-15 整理）

owner 問：Harness² 評估 harness 好壞的專業做法，我們吸收或參照了多少，能不能用在之後的 skill 吸收。
這一頁是整理，數字與細節在各自的紀錄裡。來源固定在上游 commit `6868817`（[EVALUATION.md](EVALUATION.md)）。

## 一句話

**三個候選單位裡：一個吸收了（評估帳本），一個測過、結果是不吸收（最小改動對照卡），一個還沒做（經驗索引）。它的整套 runtime 沒有試吃。
它「怎麼判斷 harness 有沒有變好」的幾條原則，已經寫進我們的量測規則，之後每一樣 skill 的吸收都會用到。**

## Harness² 是什麼

不改模型，只改模型周圍的東西（提示、守則、記憶、工具說明、subagent、skill、腳本）。它的流程是：先跑一次看哪裡失敗或浪費 →
提出幾種改法 → 每種真的跑同一題 → 對照執行紀錄 → 組合 → 選一份交付 → 事後反思。
它檢查「真的有變好」的方法：三套題庫、不同模型與 host、題目順序重排三次、拿掉某一部分再測、看能不能轉移到別的題目、把改進本身的花費算進去、列出失敗案例。

## 吸收了的

| 東西 | 從它學到什麼 | 現在在哪裡 |
|---|---|---|
| **評估帳本**（U1） | 一次比較裡，計畫要跑的每一次都列出來；失敗、重試、選擇、反思的花費照算；缺的資料標成缺、沒評分不當 0 分；題目與 harness 的版本用雜湊綁定 | `scripts/eval_ledger.py`、`docs/EVAL_LEDGER.md`，已在 `main`（2.0.1 之後）。是我們自己重寫的，沒有內附它的程式 |
| **量測規則裡的幾條原則** | 「選中了候選」不等於「證明比較好」；要另外留題目來測；改進的總花費要含被淘汰的候選；要保留「不改」這個選項；裝了但用不到時的閒置成本也要量 | `docs/EVAL_PROTOCOL.md` 的量法總覽與共用規則；`docs/SKILL_INTAKE.md` 十步流程裡的第 8、9 步 |
| **隔離的教訓** | 它自己的文件記著：沒有限制網路時，受測的 agent 下載過題目的公開評分表 | 我們在試跑時也抓到同類的事（host 內建的雲端工具繞過本機網路限制），之後每次實驗都關掉；寫在共用規則裡 |

這些已經實際用過：五個修正的複查（FIXCHECK）用帳本匯入舊資料；對照卡試跑的 runner 內附帳本與統計；
EGM 校準與對照卡試跑都照「先登記、先試跑量單價、缺的不補」做。

## 測過、不吸收的

| 東西 | 是什麼 | 結果 |
|---|---|---|
| **最小改動對照卡**（U2） | 給 `oaw-improve` 的一張參考卡：看到的問題 → 假設 → 最小的改動（先試刪、再試換，可以不改）→ 改前改後的紀錄 | 試跑 18 次：不裝任何東西的那一組全部做到；有卡片和沒卡片交出的修改逐位元組相同。照快速判定是 NO，不吸收。[紀錄](../v2.0.1-experiments/U2/PILOT_STATUS.md) |

## 還沒做、沒有拿的

| 東西 | 狀態 |
|---|---|
| **有證據、有適用範圍的經驗索引**（U3） | 沒有做。它是模型會讀的東西，要先過快速判定 |
| **它的整套 runtime**（自動提案、組合、選擇的迴圈） | 沒有試吃。官方的執行與評分走 API 計費，和「只用訂閱」衝突；沒有官方的 Claude Code 執行器；需要 Python 3.12 以上。兩題的小試跑估 Claude 約 9.2M、Codex 約 16.4M token（沒有量過），而且給不出採用判定 |
| **用平均分數排名來決定採用** | 沒有拿。我們保留自己的門檻：兩家盲評都成立才算、分「更好／等價／更差／未定」、看成本倍數 |

## 之後吸收 skill 時怎麼用

1. **先走快速判定**（[流程](https://github.com/lihowfun/O-ALL-WANT/blob/main/docs/SKILL_INTAKE.md)）：原生先跑 3 題，已經做得到就 NO；有漏才讓食物跑。這一步用不到 Harness² 的東西，目的是便宜、快。
2. **YES 之後要變成預設，才走完整的量測**：這時用帳本把每一次作答、失敗、花費都列出來，照量測規則判。Harness² 的東西用在這一步。
3. **它提醒、我們還沒有做成工具的量尺**：規則和路由的負擔（相關任務有沒有觸發、不相關的任務會不會誤觸發）、裝了但閒置時的成本、
   更新與移除是否乾淨。目前只在個別實驗裡量過（例如程式碼地圖 Opus 12 次裡 0 次自己去用、對照卡有沒有被讀到），沒有統一的工具。

## 限制

- 「吸收了」指的是方法與工具進了 repo，不是證明它們讓 OAW 變好；評估帳本本身沒有做過「有沒有幫助」的對照。
- Harness² 論文裡的效果數字我們沒有重現，也沒有採用它的結論。
