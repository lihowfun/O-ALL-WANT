Popular tools (graphify, claude-mem, TokenEconomizer, EGM) are credible references, not targets to beat. A tasting must: install the food the official way with its recommended config (project scope when offered); test its own claim at the agent level, not a tool-output proxy; have a fresh agent write the questions, frozen in records (sha256) before any run; keep model, prompt and limits equal across arms; grade blind with arm-revealing names masked. If OAW beats a popular food, suspect the test and rerun on a repo that is not OAW. Default verdict for a popular food that works is "plug in" (OAW connects to it), otherwise absorb the mechanism or decline.

**Why:** 2026-11-04 the owner: "Graphify 幾千幾萬顆星啊 你認真跑出來 我們18顆星的比較好？... 要建立最佳流程"; "3 個skills 用公正方式好好審"; "我沒有硬要重做 但你能找到值得吸收的部分當然做好". The first graphify verdict was withdrawn as unfair (home-field questions, proxy metric, no ignore file).

**How to apply:** pre-register rules in PREREG.md before runs; report ceiling effects and deviations honestly; runs use the existing subscription login; owner logins only for the one-time setup in HANDOFF §6. Related: [[feedback-taste-before-judging]], [[oaw-intake-flow-v1]].
