## 判定（照事先寫死的規則）

**Opus 5.5**
- **S：一樣懂但比較省（工具呼叫）**。
  - 覆蓋率 +0.010，錯誤陳述 1 個，N 是 4 個。
  - 工具呼叫中位數是 N 的 66%，4 題都比 N 少。
  - 省的只有工具呼叫，不是 token：每題 token 中位數是 N 的 117%。12 次合計反而少 20%，幾乎全部來自 q1。
- **G：沒有證明比原生好**。覆蓋率 −0.011，token 中位數是 N 的 128%，工具呼叫是 N 的 88%。

**Sonnet 5.5**
- **S：沒有證明比原生好**。
  - 工具呼叫是 N 的 56%，4 題都比 N 少；token 中位數是 N 的 90%；覆蓋率 −0.002。
  - 錯誤陳述 5 個，N 是 4 個，沒過「錯誤陳述不比 N 多」這一條。多出來的多半是數錯呼叫點數量這類錯誤，但規則事先寫死，照判。
- **G：沒有證明比原生好**。token 中位數是 N 的 122%；q4 有 2 次漏掉必要事實。

**合併規則（本 PREREG 的兩個條件）**
- graphify：兩個條件都沒有證明比原生好，**沒有提升**。
- OAW code map：Opus 判「比較省」，兩個條件都沒有「變差」，照本 PREREG 的字面規則算「有提升」。但省的只是工具呼叫。而且同一套規則的延伸實驗（`../codemap-erpnext-weaker/`，a801c8b 凍結，fd1895c 結果）在 Opus 4.8 上判 S「變差」：錯誤陳述多 3 個。把四個條件放在一起，就不符合「沒有任何條件變差」，**不算有提升**。

## 觀察
- **天花板效應仍在。** Opus 5.5 的原生組，12 次的必要事實全對。地圖能幫的只剩「少走幾步」，沒有空間「答得更準」。
- **OAW code map 省步數，是在影響題上。** Opus q1（`update_bin_qty` 的所有呼叫者）：S 用 `callers` 一次列出，工具呼叫 7 次，N 要 31 次；token 105k 對 220k；覆蓋率相同。機制題 q4 的 token 反而比 N 多（105k 對 72k）。
- **graphify 在影響題上比較吃力。** Opus q1 的覆蓋率 0.792，3 次裡有 1 次漏掉必要事實，token 290k。這和前一次 ERPNext 試吃看到的一致：截斷過的查詢結果要靠 grep 補齊。
- **「最多 14 次」實際上沒有限制到任何一次。** `--max-turns` 算的是回應次數，一次回應可以同時呼叫好幾個工具。36 次都沒有被切斷；`num_turns` 最多到 19，但那算的是工具結果的數量。弱模型加測也發現同一件事。所以這個條件其實是「Sonnet，並在提示裡告知有 14 次上限」，不是預算緊的條件。三組的提示都相同。
- **重複之間的差距。** 同一題 3 次的覆蓋率差距，Opus 的 N 平均 0.031、S 是 0，Sonnet 的 N 是 0.109。這個實驗分不出 0.05 以下的差距，PREREG 已事先寫明。

## 這對 owner 問題的回答
「graphify 新增 code map 讓 AI 理解，我們原先沒有這功能對吧，也要確定加進去是否能提升」：
- 原生 Claude Code 沒有 code map。OAW 在 `claude/oaw-2` 有自己的 `scripts/code_index.py`，還沒進 main，也沒有預設叫 agent 使用。
- **graphify：沒有提升。** 加上弱模型加測，共 4 個模型條件，都沒有證明比原生好，而且每題花的 token 比原生多 22% 到 28%。
- **OAW code map：讓 agent 少走步數，但沒有答得更準。** 工具呼叫少 34% 到 44%（Haiku 只跑 1 次，少 52%）。但 token 不一定省，Opus 4.8 上錯誤陳述還變多。所以「先查地圖再 grep」這條 CLAUDE.md 規則不上線。`code_index.py` 留作 agent 可以自己選用的工具。
- 這次測的是「code map 能不能讓 agent 更懂程式怎麼串在一起」。graphify 的其他功能，例如視覺化、文件和論文的多模態圖、群組命名，都沒有測。

## 不能這樣解讀
- 不能和 graphify 宣稱的 70.8% → 82.0% 並排比較：模型、工具、評分者都不同，回合上限實際上也沒有作用。
- 不能和 OAW 工具層的 39 題命中率比較，那是另一種量法。
- 樣本小：4 題，每格 3 次。
- 跨條件比較時有評分批次的差別：兩個條件各自評分，用同一個評分模型、同一段提示。

## 偏差
- Opus 的 N、G 第 1 次沿用 93e555b 的答案，和 S 的第 1 次相隔幾小時，PREREG 已事先寫明。所有答案都重新評分，上次的評分不再使用。
- 兩個條件同時在背景跑，秒數會互相影響，所以秒數不列入判定。
- 答案裡的本機試吃路徑，commit 前替換成 `<taste>/`。
