## 看到的事（量到的，不是原因）

1. **只裝著的時候，4 題都沒有叫用它。** 啟動時的清單裡有它，4 次作答都沒有 Skill 呼叫，也沒有讀它的檔案。
   題目是繁體中文；它的說明裡列的觸發詞是簡體（「优化skill」等）。兩者有沒有關係，這次沒有測。
2. **補上的 3 項，兩次是同一批，而且都在同一題（T4：60 個 skill 要全部最佳化）。**
   第一次食物組沒有載入 skill 的本文，答案裡仍然引用了它說明欄的做法（和裸模型對照實跑、盲評、只留有幫助的修改），並且做到這 3 項。
   明確呼叫之後補上的還是這 3 項，token 是 2.65 倍。T1–T3 原生本來就全部做到（10／10）。
3. **第一次的那個「弄壞」是判定模型的引句對不上。** 答案原文是 `**新舊兩版各跑一次**，把產出的摘要存下來。`，
   判定模型的引句少了 `**`，逐字核對不過，記成「不明」；照規則「不明」算弄壞。這一項若算做到，第一次也會是 YES（1.01 倍）。
   規則沒有因此改動，第一次的 NO 照記。
4. **每題只跑一次。** 原生在 T4 少的 3 項是不是每次都少，這次看不出來。

## 給規則與工具的候選（沒有動，留給下一版決定）

- 引句核對遇到 Markdown 的粗體、斜體符號就不符：要嘛核對時先去掉這些符號，要嘛在給判定模型的提示裡要求連符號一起照抄。
- 「補上至少 2 項」目前可以全部來自同一題：要不要要求來自 2 題以上。
- 「只裝著」和「明確呼叫」是兩種條件，流程裡要先講清楚篩的是哪一種。
- 這次的小型執行程式（`fs_run.py`：沙盒、全新 HOME、作答、判定、算結果）可以當成 #9「可重複使用的試吃工具」的起點。
