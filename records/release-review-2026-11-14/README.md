Opus 在第 2 輪把八個程式修正逐一還原，確認對應的新測試會失敗；Codex 在第 2 輪確認 18 個新增測試在 `b898e4d` 失敗、在 `73fb8f7` 通過。

修掉的審查發現，依後果分（14 個，加上最後一行的顯示問題共 15 個）：

- **會丟使用者資料（2）**：同一來源用更大的同意範圍再加一次，原始檔案的備份被蓋掉，移除後還原不回來（R1-01）；
  `restore`／`absorb`／已吸收 skill 的 `remove` 在取得安裝鎖之前算好要改什麼，中間被別的指令改過的自訂規則會被蓋掉（R1-02）。
- **錯誤結果（5）**：`wiki_sync` 的 `promote-candidates`、`memory-check` 讀不到含時間的新筆記標頭（C1-01，D45 修正帶進來的退步）；
  recall 排序把被取代的舊筆記排在前面（C1-02、R2-01）；排序改了但舊的翻頁游標沒失效，會漏一筆、重複一筆（R2-02）；
  開頭有一筆手寫時間的標頭，會讓整個主檔排在待併檔之後（C2-03）。
- **平台行為不一致（2）**：唯讀的主筆記檔在 Linux／macOS 被直接覆寫、在 Windows 等 3 秒後才改寫待併檔並留下暫存檔（C1-03）；
  Windows＋Python 3.10／3.11 找不到 `claude.cmd`（R2-03／C2-01，也是 CI 第 5 輪抓到的）。
- **安全相關（2）**：邊界檢查在去掉 `\\?\` 前綴後沒有正規化，`\\?\C:\proj\..\outside` 會被接受（C1-04）；
  `doctor --probe` 在舊版 Python 的 Windows 上會先找目前目錄的同名程式（C1-05）。兩個都是當天的 CI 修正帶進來、當輪就被抓到。
- **文件與實際不符（3）**：`init` 會登記 checkout 的舊說明（R1-03）；「閘門零跳過」（R1-04）；中文 README 仍寫 Claude 的模型測試未驗證（R1-05）。

另外一個顯示用的小問題（C1-06，專案根是 symlink 時印出的路徑）一併修了。

## 沒有做到或留下的

- CI 不含 Python 3.11、3.12。lead 在本機用 3.12 跑過整個閘門：修掉一個測試工具的誤判後是 9/9（#23）。
- #21：舊格式（只有日期）的筆記，在比 UTC 早的時區、同一天、而且新筆記落在待併檔時，仍可能排在新筆記前面。不丟資料。
- #22：catalog 的 bundled `remove`／`readd` 與 `forget` 還沒有同等的鎖內一致性檢查。
- 第 3 輪審查者自己的沙盒跑不完整個閘門（NFS 上 Git 拒絕 repo、沙盒不准開 socket），它的結論以重跑原始情境和相關測試為依據；完整閘門以 lead 的執行為準。
